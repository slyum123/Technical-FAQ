## 1\. SUE 协议概述

### 1.1 背景与定位

SUE（Scale-Up Ethernet）是博通（Broadcom）于 2025 年 OCP 全球峰会上发布的 AI Scale-Up 互连开放框架。其核心目标是在保持以太网生态兼容性的前提下，为 XPU（GPU/NPU/ML 加速器）集群提供超高带宽、超低延迟、无损传输的高性能通信能力。

SUE 专为 AI 超大模型训练、推理等场景设计，将传统以太网的优势（高速链路、大容量交换、成熟生态）引入 AI 系统内部的 Scale-Up 域，使得 XPU 之间的内存事务可以直接通过以太网高效搬运。

### 1.2 核心设计指标

指标| 规格| 说明
---|---|---
最大 XPU 数量| ≤ 1024| 单跳交换拓扑
端到端 RTT| < 2 μs| 往返延迟
单 SUE 带宽| 800 Gbps| 可扩展至 1.6 Tbps
SerDes 速率| 200 Gbps / lane| 兼容 100G、50G
端口配置| 1/2/4 端口| 800G 可拆分为 1×800G / 2×400G / 4×200G
单 XPU SUE 实例| 8 ~ 16 个| 多实例叠加，XPU 对间带宽可达 9.6 Tbps
虚拟通道 (VC)| ≤ 4 个| 独立流量类别，避免死锁
电缆长度| ≤ 10m| 使用空心光纤可低于 520ns 单向延迟
事务语义| 单边操作| Load / Store / Atomics

### 1.3 部署模型

SUE 支持两种典型部署拓扑：

  * **单跳交换拓扑（Single-Hop Switch）** ：每个 XPU 通过多个 SUE 实例连接到以太网交换机，所有 XPU 间最多一跳可达。典型配置：64 XPU × 12 SUE 实例 × 800G = 任意 XPU 对间 **9.6 Tbps** 。
  * **直接 Mesh 拓扑** ：XPU 之间直接通过 SUE 端口互联，无交换机参与，适用于小规模紧耦合系统。

### 1.4 六层协议栈总览

以下为本协议文档采用的分层体系——在 SUE 官方规范的三层（映射打包层 / 传输层 / 网络层）基础上，将物理层、链路层、事务层独立展开：

6 事务层 / 应用层 (Transaction / Application Layer) XPU 命令接口 · AXI4 · Load/Store/Atomics · 流量生成与消费

5 打包层 (Mapping & Packing Layer) 事务聚合 · PDU 封装 · SUE Header · 按目标 XPU+VC 组织

4 传输层 (Transport Layer) 可靠性头部 RH · PSN/RPSN · Go-Back-N 重传 · 32-bit CRC

3 网络层 (Network Layer) AFH Gen1/Gen2 · 标准 Eth/IP/UDP · SLAP 寻址 · ECN

2 链路层 (Link Layer) MAC · LLR 链路重传 · CBFC 信用流控 · PFC · 帧定界

1 物理层 (Physical Layer) SerDes 112G/224G · PAM4 · FEC RS(544,514) · PMA/PCS

## 2\. 物理层 (Physical Layer)

### 2.1 定位与职责

物理层负责在物理介质上实现比特流的透明传输，将链路层的帧转换为电信号/光信号进行发送，在接收端完成相反的转换。SUE 的物理层完全基于 IEEE 802.3 以太网标准，确保了与现有以太网生态的完全兼容。

### 2.2 核心组件

#### 2.2.1 SerDes（串行器/解串器）

#### SerDes 规格

参数| 值
---|---
单 Lane 速率| 112 Gbps（当前主流）/ 224 Gbps（下一代）
单口 Lane 数| x1 / x2 / x4 / x8
单口带宽| 112G × 8 = ~800Gbps；或 224G × 4 = ~800Gbps
调制方式| PAM4（4 电平脉冲幅度调制）
兼容性| 向下兼容 100G、50G 速率

#### 2.2.2 FEC（前向纠错）

在 100G+ 速率下，信号完整性面临严峻挑战，FEC 是保证链路可靠性的第一道防线。SUE 物理层采用 IEEE 802.3 标准 FEC 方案：

FEC 方案| 编码| 适用速率| 纠错能力| 延迟
---|---|---|---|---
FEC RS(544,514)| Reed-Solomon| 100G / 200G / 400G| 最多纠正 15 个符号错误| ~100 ns
FEC RS(272,258)| Reed-Solomon（轻量版）| 短距离低损耗链路| 最多纠正 7 个符号错误| ~50 ns

FEC 的目标是将链路误码率（BER）从 1e-5 级别降低到 1e-15 以下，足以支撑 AI Scale-Up 的可靠性需求。在无 FEC 的情况下，100G 链路上 1e-15 的 BER 意味着每 2.78 小时发生一次错误，这对 XPU 间通信是不可接受的。

#### 2.2.3 PMA / PCS 子层

  * **PCS（物理编码子层）** ：负责 64B/66B 编码、加扰、AM（对齐标记）插入、FEC 编解码。将 MAC 层的以太网帧映射为适合物理传输的编码块。
  * **PMA（物理介质连接子层）** ：负责多 Lane 的对齐、交叉（striping/de-striping）、SerDes 接口适配。
  * **PMD（物理介质相关子层）** ：负责电/光信号转换，定义连接器、电缆规格。

#### 2.2.4 传输介质

介质类型| 最大距离| 典型延迟| 应用场景
---|---|---|---
铜缆 DAC| ~3m| ~5 ns/m| 机架内同一 tray
有源光缆 AOC| ~30m| ~5 ns/m| 跨 tray / 跨机架
空心光纤 (HCF)| ~10m| ~3.3 ns/m| 极致低延迟场景（~520ns/10m 单向）

功能| 描述
---|---

## 3\. 链路层 (Link Layer)

### 3.1 定位与职责

链路层在物理层提供的不可靠比特管道之上，构建逐跳（hop-by-hop）的可靠帧传输服务。SUE 的链路层在标准以太网 MAC 层基础上，增加了 LLR（链路层重传）、CBFC（基于信用的流控）、PFC（优先级流控）等关键增强功能，是实现无损网络的核心所在。

### 3.2 核心机制

#### 3.2.1 MAC 层（介质访问控制）

遵循 IEEE 802.3 标准，负责帧定界、MAC 地址解析、FCS（帧校验序列，32-bit CRC）生成与校验。SUE 中，MAC 层处理可变长度的以太网帧（64 字节 ~ 4KB），与标准以太网完全兼容。

在 AFH Gen2 模式下，SUE 使用 SLAP（Structured Local Address Plan）机制对 MAC 地址进行压缩，但仍保持 IEEE 802 框架兼容。SLAP 在 M/X/Y/Z 四个比特位上编码地址模式：

M| X| Y| Z| 模式| 说明
---|---|---|---|---|---
*| *| 0| 0| AA（管理分配）| SUE Gen2 采用，X=1 表示本地管理
*| *| 0| 1| SA（标准分配）| IEEE 注册 MAC
*| *| 1| 0| EL（扩展本地）| 扩展本地地址
*| *| 1| 1| 预留| —

#### 3.2.2 LLR（Link-Level Retry，链路层重传）

#### LLR 工作机制

LLR 在链路层提供逐跳的无损传输保障，其核心思想是在物理层 FEC 失效后，由链路层进行快速重传，无需端到端超时。

特性| 描述
---|---
检测机制| 接收端通过 CRC-32（FCS）校验检测帧损坏
反馈机制| 通过特殊的控制有序集（Control Ordered Sets）注入 64B/66B 数据流，同步携带 ACK/NACK
重传缓冲区| 发送端维护每个帧的副本，直到收到 ACK
重传粒度| 单个损坏帧级别，不影响其他帧
恢复延迟| 典型 < 100ns（单跳链路往返 + 处理）
兼容性| 遵循 UEC（Ultra Ethernet Consortium）LLR 规范草案

#### 3.2.3 CBFC（Credit-Based Flow Control，基于信用的流控）

CBFC 是 SUE 实现无损传输的关键流控机制，替代了传统以太网的 PFC（Priority Flow Control），消除了 PFC 的队头阻塞（HOL Blocking）和死锁问题。

**工作原理：**

  1. **信用初始化** ：接收端为每个虚拟通道（VC）通告其可用缓冲区大小（初始信用值）。
  2. **信用消耗** ：发送端每发送一帧数据，消耗对应 VC 的信用值（消耗量 = 帧大小）。
  3. **信用返还** ：接收端处理完帧、释放缓冲区后，通过控制有序集向发送端发送信用返还消息。
  4. **流控阻塞** ：当某 VC 的信用值为 0 时，发送端暂停该 VC 的数据发送，但不影响其他 VC。

**CBFC vs PFC：** CBFC 是预防性流控——发送端在信用耗尽时提前停止发送，保证接收端缓冲区永不溢出。PFC 是反应性流控——接收端缓冲区快满时才发送 PAUSE 帧。CBFC 在两个关键指标上优于 PFC：消除队头阻塞（按 VC 独立控制）、减少缓冲区需求（约 PFC 的一半）。

#### 3.2.4 PFC（Priority Flow Control）

在 CBFC 不可用或兼容模式下，SUE 也支持标准 PFC（IEEE 802.1Qbb）。PFC 按优先级独立进行 PAUSE/UNPAUSE 控制，但在 Clos 拓扑中已知存在队头阻塞问题。在 SUE 单跳交换拓扑中，PFC 性能尚可接受。

#### 3.2.5 虚拟通道 (VC, Virtual Channels)

SUE 支持最多 4 个独立的虚拟通道（VC），每个 VC 映射到一个流量类别（Traffic Class）。VC 用于：

  * **避免协议级死锁** ：将请求（Request）和响应（Response）分配到不同 VC，防止请求-响应循环死锁。
  * **QoS 隔离** ：高优先级控制消息与大数据传输隔离，保证控制面的低延迟。
  * **消除队头阻塞** ：每个 VC 拥有独立的缓冲区队列和 CBFC 信用管理。

### 3.3 Ethernet 接口

SUE 的以太网接口支持灵活的端口拆分和故障切换：

  * **端口配置** ：1x800G / 2x400G / 4x200G，灵活匹配交换机端口密度。
  * **动态故障链路切换** ：检测到某 Lane 故障时自动屏蔽并使用剩余 Lane 降速运行。
  * **冗余设计** ：多端口模式天然支持端口级冗余。

### 3.4 链路层功能总结

功能| 机制| 描述
---|---|---
帧定界| MAC + PPP Header| 以太网帧起始/结束标记，前导码 + SFD
帧校验| CRC-32 (FCS)| 帧尾 32 位循环冗余校验，检测传输错误
链路可靠性| LLR| 逐跳 ACK/NACK + 缓冲区重传，恢复延迟 <100ns
无损流控| CBFC / PFC| 基于信用的预防性流控，按 VC 独立管理
虚拟通道| VC (≤4)| 独立流量类别隔离，消除队头阻塞和协议死锁
链路管理| Auto-Negotiation| 速率协商、FEC 协商、链路训练

## 4\. 网络层 (Network Layer)

### 4.1 定位与职责

网络层负责将传输层的 SUE PDU 封装为可路由的网络数据包，并在 Scale-Up 交换网络中将其从源 XPU 转发到目的 XPU。SUE 的网络层支持多种封装格式，从标准以太网到极致压缩的 AI 转发头，在不同场景间灵活选择。

### 4.2 三种封装模式

#### 4.2.1 模式一：标准以太网/IP/UDP 封装

完全兼容标准网络协议栈，适用于需要与现有基础设施互通的场景。开销较大（约 46 字节头部），但在非极致性能场景下提供了最大的灵活性。

#### 4.2.2 模式二：AFH Gen1（优化 AI 转发头）

AFH（AI Forwarding Header）Gen1 在标准以太网帧头基础上添加 Shim Header，保留 L2 兼容性同时压缩了 L3/L4 信息。与 ESUN v1.0 技术路线一致。

AFH Gen2 是 SUE 协议的显著技术亮点——将 L2/L3/L4 多层信息融合压缩到 12 字节的单一头部，通过 SLAP 机制实现灵活寻址。在 128 字节 cacheline 传输场景下，载荷比可达 84.2%（含前导码和 FCS）。

### 4.3 AFH Gen1 vs Gen2 对比

维度| AFH Gen1| AFH Gen2
---|---|---
设计理念| 兼容优先（堆叠式）| 性能优先（融合式）
头部开销| 16 ~ 17 字节| 12 字节
寻址方式| 标准 48-bit MAC| SLAP 压缩 (16/32 bit)
载荷比（128B）| ~81%| ~84.2%
兼容性| 原生兼容标准以太网| 需要交换芯片支持 SLAP
适用场景| 快速部署、混合环境| 极致性能、封闭 Scale-Up 域

### 4.4 交换转发

在 SUE 单跳交换拓扑中，以太网交换机基于目的 MAC 地址（或 AFH Gen2 压缩地址）进行静态转发：

  * **静态转发** ：无 MAC 学习/老化，基于预配置的转发表进行确定性转发。
  * **禁止广播** ：未知目的地址不出端口广播，直接丢弃（避免 Scale-Up 域的广播风暴）。
  * **Cut-Through 转发** ：交换机在接收到足够转发的头部后即可开始转发，无需等待整个帧接收完毕，典型交换延迟 250~300ns。
  * **ECN 标记** ：当交换机队列拥塞时，在 AFH 头部标记 ECN 位，通知发送端降速。

## 5\. 传输层 (Transport Layer)

### 5.1 定位与职责

传输层在链路层的逐跳可靠性和网络层的报文转发之上，提供**端到端（End-to-End）的可靠传输服务** 。它通过可靠性头部（RH）、序列号（PSN）、确认机制（RPSN）和简化的 Go-Back-N 重传协议，确保在发生链路闪断、交换机缓冲区溢出等不可恢复错误时，数据仍能从源 XPU 完整地传递到目的 XPU。

**注意：** SUE Lite 版本去除了传输层 RH 和端到端重传，将可靠性完全交给链路层的 LLR + CBFC。完整版 SUE 才包含传输层端到端可靠性保障。

### 5.2 可靠性头部 (RH, Reliability Header)

RH 是 SUE 传输层的核心数据结构，附加在每个 SUE PDU 的前部：

┌────────────────────────────────────────────────────────────┐ │ SUE 传输层 RH（Reliability Header） │ ├──────────┬──────────┬──────────┬──────────┬────────────────┤ │ PSN │ VC │ RPSN │ Flags │ R-CRC (32b) │ │ (16 bit) │ (3 bit) │ (16 bit) │ (5 bit) │ │ ├──────────┴──────────┴──────────┴──────────┴────────────────┤ │ │ │ PSN (Packet Sequence Number, 16 bits): │ │ 发送序列号，每个 SUE PDU 递增，用于检测丢失和重排序 │ │ │ │ VC (Virtual Channel, 3 bits): │ │ 虚拟通道标识，0~7（SUE 最多 4 个 VC） │ │ │ │ RPSN (Received PSN, 16 bits): │ │ 累积确认号——确认已成功收到的最后一个连续 PDU 的 PSN │ │ (Go-Back-N 机制的累积 ACK) │ │ │ │ Flags (5 bits): │ │ · ACK/NACK 标志位 │ │ · E2E 拥塞通知标志 │ │ · 保留位 │ │ │ │ R-CRC (Reliability CRC, 32 bits): │ │ 对 RH + Payload 的独立 CRC-32 校验，与链路层 FCS 互补 │ └────────────────────────────────────────────────────────────┘

### 5.3 Go-Back-N 重传机制

SUE 传输层采用**简化的 Go-Back-N** 协议，这是一种为 Scale-Up 低延迟、低复杂度场景优化的方案：

#### 5.3.1 为什么选择 Go-Back-N？

  * **硬件简洁性** ：Go-Back-N 的接收端只需维护一个期望的 PSN，无需乱序缓冲区，非常适合 XPU 的硬件实现。
  * **低延迟环境** ：Scale-Up 网络 RTT < 2μs，Go-Back-N 的 "重传窗口内所有包" 策略代价可控。
  * **罕见触发** ：在大部情况下，LLR + CBFC 已经实现了无损传输，传输层重传仅在链路闪断等极端场景才被触发。

#### 5.3.2 工作流程

#### Go-Back-N 发送端流程

  1. 为每个 PDU 分配递增的 PSN（16-bit 回绕）。
  2. 发送 PDU 后保留副本在重传缓冲区中。
  3. 维护发送窗口：`base`（最早未确认 PSN）和 `next_seq`（下一个待分配 PSN）。
  4. 收到带有 RPSN 的 ACK 帧时，将 base 滑动到 RPSN+1，释放已确认 PDU 的缓冲区。
  5. 超时（典型 ~1μs）未收到 ACK 时，从 base 开始重传窗口内所有未确认 PDU。

#### Go-Back-N 接收端流程

  1. 维护 `expected_seq`（期望的下一个 PSN）。
  2. 收到 PDU，检查 PSN：
     * 若 PSN == expected_seq → 接受，递交给上层，expected_seq++，发送 ACK(RPSN=PSN)。
     * 若 PSN != expected_seq → 丢弃（乱序或重复），发送 ACK(RPSN=expected_seq-1)。
  3. 检测到 PDU 损坏（R-CRC 校验失败）→ 发送 NACK。

#### 5.3.3 闪断恢复

SUE 传输层的一个关键能力是利用 RH 中的 PSN 在 1μs 内从链路闪断中恢复。当链路短暂中断后恢复时：

  1. 接收端发现 PSN 不连续，发送 ACK(RPSN=最后连续 PSN)。
  2. 发送端收到 ACK 后，从断点开始 Go-Back-N 重传。
  3. 由于 RTT 极低（<2μs），整个恢复过程在 1μs 级别完成。

### 5.4 排序模式

SUE 传输层支持两种排序模式，由 XPU 根据业务需求选择：

模式| 说明| 适用场景
---|---|---
**严格有序 (Strict Ordering)**|  源和目标之间特定 VC 上的所有事务按发送顺序依次递交。Go-Back-N 接收端自然保证有序。| 需要严格保序的内存操作（如原子操作序列）
**无序 (Unordered)**|  多端口模式下，事务在端口间负载均衡，不保持全局顺序。不保证多平面保序，需端侧将保序 stream 放在同一 port。| 大量独立的内存读写（最大化带宽利用率）

### 5.5 传输层功能总结

功能| 机制| 描述
---|---|---
序列号管理| PSN (16-bit)| 每个 PDU 的唯一单调递增标识，检测丢失和重复
确认机制| RPSN (累积 ACK)| Go-Back-N 累积确认，减少 ACK 报文数量
端到端重传| Go-Back-N| 超时后重传窗口内所有未确认 PDU
端到端校验| R-CRC (32-bit)| 独立于链路层 FCS 的端到端完整性校验
排序保证| Strict / Unordered| 严格有序模式和无序模式可选
拥塞通知| RH Flags| 端到端拥塞状态传递

## 6\. 打包层 (Mapping & Packing Layer)

### 6.1 定位与职责

打包层（亦称为映射打包层）位于事务层和传输层之间，是 SUE 协议栈中的关键效率优化层。它负责将上层事务层下发的小粒度事务命令，按目的地和虚拟通道组织聚合，形成更大粒度的 SUE PDU（Protocol Data Unit），从而提升链路利用率和有效载荷比。

**核心思想：** AI Scale-Up 场景中，XPU 之间的内存事务通常为小粒度传输（如 128 字节的 cacheline）。如果每个事务都独立封装为以太网帧，网络头部开销将极为显著。打包层通过将多个小事务聚合为一个大 PDU，分摊头部开销，显著提升有效带宽。

### 6.2 事务到 PDU 的映射流程

#### 6.2.1 事务队列组织

SUE 维护一个二维队列矩阵，按 **(目标 XPU, VC)** 组织：

┌──────────────────────────────────────────────────────────┐ │ SUE 打包层事务队列矩阵 │ │ │ │ ┌──────────┬──────────┬──────────┬──────────┐ │ │ │ VC0 │ VC1 │ VC2 │ VC3 │ │ │ ┌───────┼──────────┼──────────┼──────────┼──────────┤ │ │ │XPU_0 │ Queue[0] │ Queue[4] │ Queue[8] │ Queue[C] │ │ │ │XPU_1 │ Queue[1] │ Queue[5] │ Queue[9] │ Queue[D] │ │ │ │ ... │ ... │ ... │ ... │ ... │ │ │ │XPU_N │ Queue[N] │ Queue[...]│Queue[...]│Queue[...]│ │ │ └───────┴──────────┴──────────┴──────────┴──────────┘ │ │ │ │ 每个队列中的事务按到达顺序排列，等待打包 │ └──────────────────────────────────────────────────────────┘

#### 6.2.2 打包策略

#### 机会性打包（Opportunistic Packing）

SUE 持续监控每个 (XPU, VC) 队列的深度。当某队列中累积了多个事务时，打包器在**不引入额外延迟** 的前提下，将队列中的待发送事务拼接为单个 PDU：

  1. 从队列头部开始取事务。
  2. 将事务的 Command 字段 + Data（若有）连续拼接。
  3. 当总长度达到 **4096 字节上限** 或 队列为空时停止。
  4. 为聚合后的数据块添加 SUE Header，形成 PDU。

**零延迟承诺** ：打包器在每个调度周期检查队列——如果队列中只有一个事务，则直接发送单个事务的 PDU，不会等待更多事务到来而引入打包延迟。这保证了低负载下的低延迟。

#### 6.2.3 SUE PDU 格式

┌──────────────────────────────────────────────────────────┐ │ SUE PDU (Protocol Data Unit) 格式 │ │ 最大长度: 4096 Bytes │ ├───────────┬──────────────────────────────────────────────┤ │ SUE Hdr │ Payload（1~N 个事务拼接） │ ├───────────┼──────────────────────────────────────────────┤ │ │ ┌──────────────┬─────────────────────────┐ │ │ │ │ Transaction 1 │ Cmd + Data (optional) │ │ │ │ ├──────────────┼─────────────────────────┤ │ │ │ │ Transaction 2 │ Cmd + Data (optional) │ │ │ │ ├──────────────┼─────────────────────────┤ │ │ │ │ ... │ ... │ │ │ │ ├──────────────┼─────────────────────────┤ │ │ │ │ Transaction N │ Cmd + Data (optional) │ │ │ │ └──────────────┴─────────────────────────┘ │ ├───────────┴──────────────────────────────────────────────┤ │ SUE Header 字段: │ │ · Src_XPU_ID — 源 XPU 标识 │ │ · Dst_XPU_ID — 目标 XPU 标识 │ │ · VC — 虚拟通道 │ │ · Tx_Count — PDU 中包含的事务数量 │ │ · PDU_Length — PDU 总长度 │ │ · Flags — 事务边界标志、控制标志 │ └──────────────────────────────────────────────────────────┘

### 6.3 接收端解包流程

接收端的解包过程是发送端的逆过程：

  1. 传输层验证 PSN 顺序和 R-CRC 完整性后，将完整 PDU 递交给打包层。
  2. 打包层解析 SUE Header，获取事务数量（Tx_Count）。
  3. 逐个提取每个事务的 Command 和 Data，递交给事务层。
  4. 事务层按操作码、目标地址等字段路由到 XPU 内部对应的处理单元。

### 6.4 打包效率分析

打包层的存在对 SUE 的整体效率至关重要。下表展示了不同事务大小和打包策略下的有效载荷比：

场景| 单事务大小| PDU 内事务数| PDU 总长| 头部开销| 载荷比
---|---|---|---|---|---
零散小事务（无打包）| 128 B| 1| ~140 B| SUE Hdr + AFH Gen2 = ~20 B| ~85.7%
满载打包| 128 B| 32| 4096 B| SUE Hdr + AFH Gen2 = ~20 B| ~99.5%
满载打包| 64 B| 64| 4096 B| SUE Hdr + AFH Gen2 = ~20 B| ~99.5%
中等打包| 256 B| 16| 4096 B| SUE Hdr + AFH Gen2 = ~20 B| ~99.5%

可以看出，打包层在高负载场景下将头部开销几乎完全摊薄，是实现超高带宽利用率的关键设计。

### 6.5 打包层功能总结

功能| 描述
---|---
事务分类| 按 (目标 XPU, VC) 将事务分发到对应队列
机会性聚合| 将同队列的多个事务拼接为单个 PDU，最大 4096 字节
零延迟打包| 低负载时不做等待，直接发送单事务 PDU

PDU 解包| 接收端解析 SUE Header，逐个提取事务递交给事务层

## 7\. 事务层 / 应用层 (Transaction & Application Layer)

### 7.1 定位与职责

事务层是 SUE 协议栈的最顶层，直接与 XPU 的内部片上网络（NoC）或内存子系统交互。事务层负责生成和消费 SUE 事务命令，将 XPU 的内存操作（Load/Store/Atomics）转化为 SUE 协议栈可处理的标准化命令格式。

### 7.2 XPU 命令接口

#### 7.2.1 接口类型

#### 命令接口 (Command Interface)

SUE 提供类 AXI 或 AXI4 接口的信号全双工（Signal Duplex）数据接口，是 XPU 与 SUE 之间的主要事务通道。

模式| 描述
---|---
FIFO 信用模式| 基于信用的流控，硬件实现简单，适合高吞吐场景
AXI4 总线模式| 标准 AMBA AXI4 接口，支持 outstanding transaction，兼容现有 XPU 设计

**控制字段（144 bits 典型）：**

  * Opcode（操作码）— 读/写/原子操作/读响应/写响应
  * Length — 数据长度
  * Dst_XPU_ID — 目标 XPU 标识符
  * VC — 虚拟通道选择
  * Address — 目标内存地址（若适用）
  * 其他 — 事务 ID、Flags 等

#### 7.2.2 管理接口 (Management Interface)

基于 AXI 的寄存器配置通道（AXI-Lite 或 AXI4），用于：

  * SUE 实例配置（端口数、速率、FEC 模式、LLR 开关等）
  * 状态寄存器读取（链路状态、错误计数器、性能统计）
  * 中断管理和错误上报

### 7.3 事务语义

SUE 将所有 XPU 间交互视为**命令/响应事务** 。命令的具体操作集和结构是 XPU 特定的，对 SUE 是透明的（opaque），这使得 SUE 可以适配不同厂商的 XPU：

事务类型| 方向| 携带数据| 描述
---|---|---|---
**Put (Write)**|  源 → 目标| 是（数据）| 将数据写入目标 XPU 内存
**Get (Read Request)**|  源 → 目标| 否（仅地址）| 请求读取目标 XPU 内存
**Read Response**|  目标 → 源| 是（数据）| 返回读取的数据
**Atomic**|  源 → 目标| 是（操作数）| 原子操作（CAS、FADD 等）
**Atomic Response**|  目标 → 源| 是（结果）| 返回原子操作结果
**Write Ack**|  目标 → 源| 否| 写操作完成确认

### 7.4 VC 映射与死锁避免

事务层的一个关键职责是将不同的事务类型映射到不同的虚拟通道，以避免协议级死锁：

┌──────────────────────────────────────────────────────────┐ │ SUE VC 映射策略（典型配置） │ │ │ │ VC0 — 请求通道 (Request) │ │ · Put (Write) Request │ │ · Get (Read) Request │ │ · Atomic Request │ │ │ │ VC1 — 响应通道 (Response) │ │ · Read Response │ │ · Atomic Response │ │ · Write Ack │ │ │ │ VC2 / VC3 — 预留 │ │ · 高优先级控制消息 │ │ · 系统管理消息 │ │ · 集合通信（可选） │ └──────────────────────────────────────────────────────────┘

将请求和响应分离到不同的 VC 是避免请求-响应循环死锁的经典方案，这也被 PCIe、NVLink 等协议广泛采用。

### 7.5 应用层：流量生成与消费

在 SUE 的软件仿真和实际部署中，应用层负责根据工作负载配置生成流量模式：

  * **流量生成器 (Traffic Generator)** ：按指定速率、事务大小分布、目标 XPU 分布生成合成流量或重放 Trace。
  * **负载均衡器 (Load Balancer)** ：在 XPU 的多个 SUE 实例之间分发事务，避免热点。
  * **性能监控 (Performance Monitor)** ：记录端到端延迟、吞吐量、重传率等指标。

### 7.6 事务层功能总结

功能| 描述
---|---
命令生成| 将 XPU 内存操作转化为 SUE 标准命令格式（Opcode + 地址 + 数据 + 控制）
命令解析| 接收端解析命令，路由到 XPU 内存子系统对应单元
VC 映射| 按事务类型映射到不同 VC，避免死锁
流量控制| FIFO 信用 / AXI4 反压，防止 XPU 溢出 SUE 缓冲区
管理配置| 通过管理接口配置 SUE 实例参数、读取状态
负载均衡| 跨 SUE 实例分发事务

┌─ CBFC 流控动态 ───────────────────────────────────────────┐ │ │ │ 初始状态: VC0 Credit = 64KB, VC1 Credit = 64KB │ │ │ │ T0: 发送端发送 48KB VC0 数据 │ │ → VC0 Credit = 16KB (正常) │ │ │ │ T1: 发送端发送 20KB VC0 数据 │ │ → VC0 Credit = -4KB → 信用不足，暂停 VC0 发送 │ │ → VC1 不受影响，继续发送 │ │ │ │ T2: 接收端处理完 32KB VC0 数据，返还 32KB 信用 │ │ → VC0 Credit = 28KB → 恢复 VC0 发送 │ │ │ │ 关键优势: VC 独立信用管理 → 一个 VC 阻塞不影响其他 VC │ └──────────────────────────────────────────────────────────┘

#### 8.3.4 场景四：传输层闪断恢复（Go-Back-N）

┌─ 链路闪断恢复流程 ────────────────────────────────────────┐ │ │ │ 正常传输中: PSN 100, 101, 102, 103, 104... │ │ │ │ ▼ 链路闪断 (LLR 也失败) │ │ PSN 103, 104, 105 丢失 │ │ │ │ ▼ 链路恢复 │ │ 发送端继续: PSN 106 (发送窗口内) │ │ 接收端: expected=103, 收到 PSN=106 → 丢弃! │ │ 接收端: 发送 ACK(RPSN=102) │ │ │ │ ▼ 发送端收到 ACK(RPSN=102) │ │ 发现 base=103, 触发 Go-Back-N │ │ 从 PSN 103 开始重传: 103, 104, 105, 106... │ │ │ │ ▼ 接收端: │ │ PSN 103 ✓ → ACK(RPSN=103) │ │ PSN 104 ✓ → ACK(RPSN=104) │ │ ... │ │ │ │ 恢复延迟: ~1μs (取决于窗口大小和链路速率) │ └──────────────────────────────────────────────────────────┘

### 9.1 系统级架构总览

### 9.2 核心组件详解

#### 9.2.1 SUE 实例 (SUE Instance)

SUE 实例是 SUE 协议栈的硬件/固件实现单元。每个 XPU 内部可集成 8~16 个 SUE 实例，每个实例：

  * 独立运行完整的六层协议栈
  * 可配置为 1/2/4 个物理端口
  * 拥有独立的 CBFC 信用管理、LLR 重传缓冲区
  * 通过负载均衡器与其他实例协同工作

多实例叠加是实现超高带宽的关键——64 XPU × 12 SUE 实例 × 800G = 任意 XPU 对间 9.6 Tbps。

#### 9.2.2 SUE 驱动层

SUE 驱动是运行在 XPU 主机侧（或嵌入式管理核）的软件组件，提供以下核心服务：

模块| 功能
---|---
实例管理器| 多 SUE 实例的生命周期管理——初始化、配置、启动、停止、复位
DMA 引擎接口| 建立 XPU 本地内存与 SUE 命令接口之间的 DMA 通道，支持零拷贝数据传输
地址映射| 管理远程 XPU 的共享内存地址空间映射（PGAS 模型），将全局地址翻译为 (XPU_ID, Local_Addr)
中断处理| 接收 SUE 的完成中断（事务完成、错误通知、链路状态变化），分发到上层处理函数
性能监控| 采集延迟直方图、吞吐量时间序列、重传率、信用利用率等指标，上报到集群管理器
错误处理| 链路故障检测、SUE 实例故障隔离、自动降级/恢复

#### 9.2.3 硬件抽象层 (HAL)

HAL 提供了 SUE 硬件寄存器的统一访问接口，屏蔽不同版本 SUE 硬件的差异：

  * **寄存器读写** ：通过 AXI-Lite 总线或 PCIe BAR 空间访问 SUE 配置和状态寄存器。
  * **命令队列 (SQ/CQ)** ：Submission Queue（提交队列）用于 XPU 向 SUE 提交事务命令；Completion Queue（完成队列）用于 SUE 向 XPU 通知事务完成。
  * **管理接口** ：用于配置 SUE 参数（端口模式、FEC 类型、LLR 开关、VC 数量等）。

#### 9.2.4 集群管理器

集群管理器是 SUE 生态的顶层软件，负责整个 Scale-Up 集群的编排和运维。博通已推动将 SUE 集成到 **SONiC (Software for Open Networking in the Cloud) Scale-Up WG** 中：

功能域| 描述
---|---
拓扑发现| 自动发现所有 SUE 实例和交换机端口，构建 XPU 互联拓扑图
路由管理| 计算并下发静态转发表，支持基于 Flow Label 的负载均衡
故障管理| 链路 Down/Up 事件处理、故障域隔离、冗余路径切换
配置管理| 批量配置下发（SUE 参数、交换机端口配置、QoS 策略）
遥测采集| 实时采集延迟、带宽、错误率等指标，支持 AI 训练作业的性能调优
固件升级| SUE 固件和交换机固件的滚动升级

### 9.3 数据路径与控制路径分离

#### 双路径架构

| 数据路径 (Data Path)| 控制路径 (Control Path)
---|---|---
功能| XPU 间内存事务的高速传输| SUE 配置、状态监测、错误处理
接口| 命令接口 (AXI4/FIFO)| 管理接口 (AXI-Lite)
延迟要求| **极低延迟** （亚微秒级）| 延迟不敏感（毫秒级可接受）
带宽要求| **超高带宽** （Tbps 级）| 低带宽（Mbps 级足够）
实现方式| 硬件加速（全流水线）| 固件 + 驱动软件

这种分离设计确保了控制面操作不会干扰数据面的极致性能，是高性能互连协议的标准实践。

### 9.4 与 AI 训练框架的集成

SUE 在 AI 软件栈中的位置以及与上层训练框架的关系：

┌──────────────────────────────────────────────────────────┐ │ AI 软件栈与 SUE 集成 │ │ │ │ ┌────────────────────────────────────────────────────┐ │ │ │ AI 训练框架 (PyTorch / JAX / TensorFlow) │ │ │ │ · 模型定义 · 自动微分 · 优化器 │ │ │ └───────────────────┬────────────────────────────────┘ │ │ │ │ │ ┌───────────────────┴────────────────────────────────┐ │ │ │ 集合通信库 (NCCL / RCCL / OneCCL) │ │ │ │ · AllReduce / AllGather / ReduceScatter │ │ │ │ · 将集合操作映射为 SUE Put/Get 原语 │ │ │ └───────────────────┬────────────────────────────────┘ │ │ │ │ │ ┌───────────────────┴────────────────────────────────┐ │ │ │ SUE 通信原语 │ │ │ │ · sue_put(dst, addr, data, len) │ │ │ │ · sue_get(dst, addr, len) → data │ │ │ │ · sue_atomic(dst, addr, op, val) → result │ │ │ │ · sue_fence() / sue_flush() │ │ │ └───────────────────┬────────────────────────────────┘ │ │ │ │ │ ┌───────────────────┴────────────────────────────────┐ │ │ │ SUE 驱动 + SUE 硬件 │ │ │ │ (六层协议栈，低延迟高带宽传输) │ │ │ └────────────────────────────────────────────────────┘ │ └──────────────────────────────────────────────────────────┘

当前主要的集合通信库（如 NCCL）通过插件或适配层将 AllReduce 等集合操作映射为 SUE 的 Put/Get 原语，从而利用 SUE 的高带宽和低延迟特性加速分布式训练。

## 10\. 总结与附录

### 10.1 六层协议栈汇总

层次| 名称| 核心协议/机制| 关键数据结构| 主要职责
---|---|---|---|---
**6** | 事务层/应用层 | AXI4 / FIFO / Load-Store-Atomics | Command (144-bit) | XPU 内存操作生成与消费、VC 映射、流量生成
**5** | 打包层 | Opportunistic Packing | SUE PDU (≤4096B) | 按 (XPU, VC) 聚合事务、零延迟打包、PDU 解包
**4** | 传输层 | RH / Go-Back-N / PSN-RPSN | RH (PSN+VC+RPSN+R-CRC) | 端到端可靠传输、序列号管理、闪断恢复
**3** | 网络层 | AFH Gen1/Gen2 / Eth/IP/UDP | AFH Gen2 (12B) / AFH Gen1 (17B) | 多模式封装寻址、静态转发、ECN 拥塞管理
**2** | 链路层 | LLR / CBFC / PFC / MAC | Ethernet Frame (64B~4KB) | 逐跳可靠传输、信用流控、虚拟通道隔离、帧校验
**1** | 物理层 | IEEE 802.3 / PAM4 / RS-FEC | 64B/66B 编码块 | SerDes 112G/224G、前向纠错、信号完整性与链路训练

### 10.2 可靠性分层保障体系

3 传输层 — 端到端可靠性 Go-Back-N 重传 · RH/PSN/R-CRC · 闪断恢复 ≤1μs · 多跳拓扑

2 链路层 — 逐跳可靠性 LLR 链路重传 ~100ns · CBFC 无损流控 · CRC-32 帧校验

1 物理层 — 信号级可靠性 RS-FEC · PAM4 均衡 · 链路训练 · BER 1e-15

### 10.3 SUE 协议关键创新点

  1. **融合式报文头压缩（AFH Gen2 + SLAP）** ：将 L2/L3/L4 头部压缩至 12 字节，128 字节 payload 下载荷比 84.2%。
  2. **机会性零延迟打包** ：在 MTU 限制内动态聚合事务，高负载下将头部开销几乎完全摊薄。
  3. **三层可靠性金字塔** ：物理层 FEC → 链路层 LLR → 传输层 Go-Back-N，层层递进保障。
  4. **基于信用的流控（CBFC）** ：按 VC 独立管理信用，彻底消除 PFC 的队头阻塞和死锁问题。
  5. **双版本策略（完整版 / Lite）** ：根据网络规模和可靠性需求灵活选择，平衡复杂度与性能。
  6. **以太网生态兼容** ：在物理层和链路层保持 IEEE 802.3 兼容，复用成熟的 SerDes、交换机芯片和运维工具链。
