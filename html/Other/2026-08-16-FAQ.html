Vite + React + TypeScript 项目搭建最佳实践

分类： Computer · 前端工程化

问题描述： 如何快速搭建一个现代 React 项目，兼顾开发体验、类型安全和构建性能？

回答要点

  • 脚手架选择：使用 npx create-vite@latest --template react-ts 创建项目，自动配置 TypeScript + Vite + React 基础结构
  • 核心依赖栈：
    • react@18 + react-dom@18 — UI 框架
    • typescript@5 — 类型系统
    • vite@5 — 构建工具（ESM 原生开发服务器 + Rollup 生产打包）
    • tailwindcss@3 — 原子化 CSS 框架
    • framer-motion — 声明式动画库
    • lucide-react — 图标库
  • 路径别名配置：在 tsconfig.json 和 vite.config.ts 中同步配置 @/ 指向 src/
  • 开发命令： 
    npm install        # 安装依赖
npm run dev        # 启动开发服务器 (默认 5173 端口)
npm run build      # 构建到 dist/
npm run preview    # 预览构建产物
  • 项目结构约定：
    • src/data/ — 内容数据层（纯数据文件，便于维护）
    • src/sections/ — 页面区块组件
    • src/components/ — 可复用 UI 组件
    • src/types/ — TypeScript 类型定义
    • src/hooks/ — 自定义 Hooks
    • scripts/ — 构建辅助脚本（CommonJS 格式）
关键结论：Vite + React + TS 是当前前端项目的主流技术选型，核心优势在于 Vite 的 ESM 原生 HMR（毫秒级热更新）和 Rollup 生产打包。将内容数据与 UI 组件分离（src/data/ vs src/sections/）可显著降低维护成本。

Tailwind CSS + shadcn/ui 暗色主题组件体系

分类： Computer · 前端样式

问题描述： 如何使用 Tailwind CSS 和 shadcn/ui 构建一致的暗色主题 UI？

回答要点

  • Tailwind 配置：在 tailwind.config.js 中扩展自定义颜色变量，映射到 CSS 变量以支持主题切换： 
    module.exports = {
  darkMode: 'class',
  theme: {
    extend: {
      colors: {
        background: 'hsl(var(--background))',
        foreground: 'hsl(var(--foreground))',
        primary: 'hsl(var(--primary))',
      }
    }
  }
}
  • shadcn/ui 初始化：运行 npx shadcn-ui@latest init，选择暗色主题，生成 components.json 配置文件和 CSS 变量
  • CSS 变量体系：暗色主题使用深色背景 + 高对比度文字：
    • 背景：#0d1117（GitHub Dark 风格）
    • 文字：#c9d1d9
    • 强调色：蓝紫渐变 #58a6ff → #bc8cff
    • 边框：#30363d
  • 组件按需引入：shadcn/ui 采用 Copy-Paste 模式，组件代码直接复制到项目中，可自由修改
  • PostCSS 配置：需安装 autoprefixer 和 postcss，配置 postcss.config.js
关键结论：shadcn/ui 的 Copy-Paste 模式比传统 npm 组件库更灵活——组件源码在项目内，可完全控制样式和行为。配合 Tailwind CSS 变量系统，可轻松实现一致的暗色主题。

GitHub Pages 部署：构建产物直接推送方案

分类： Computer · 持续部署

问题描述： 如何将 Vite 构建的静态网站部署到 GitHub Pages？

回答要点

  • 方案选择：采用构建产物直接推送方案——将 dist/ 目录内容推送到 <username>.github.io 仓库的 main 分支
  • 部署流程： 
    npm run build
cd dist
git init -b main
git add -A
git commit -m "deploy"
git remote add origin https://github.com/<user>/<user>.github.io.git
git push -f origin main
  • 源码仓库分离：源码托管在独立仓库（如 portfolio），部署仓库仅含构建产物，保持历史干净
  • gh CLI 认证：使用 gh auth login 完成 GitHub CLI 认证，后续 git push 无需手动输入凭据
  • Vite base 路径：若部署在子路径（如 /repo-name/），需在 vite.config.ts 中设置 base: '/repo-name/'；部署到 <user>.github.io 根域名则无需设置
  • Pages 生效时间：推送后 GitHub Pages 约 1-2 分钟完成构建部署
  • Windows 注意事项：Windows 下 rm -rf dist 可能被 safe-delete shim 拦截，需先手动删除或使用空目录策略再构建
关键结论：构建产物直接推送是最简单的 GitHub Pages 部署方案，无需 CI/CD 配置。源码仓库与部署仓库分离是最佳实践——源码在独立仓库版本管理，部署仓库仅含 dist/ 产物。推送后用 git push -f 覆盖历史，保持部署仓库整洁。

Framer Motion 滚动动画与卡片悬浮效果实现

分类： Computer · 前端动画

问题描述： 如何使用 Framer Motion 实现页面滚动渐入动画和卡片悬浮发光效果？

回答要点

  • 滚动渐入动画：使用 whileInView 属性配合 viewport 配置： 
    <motion.div
  initial={{ opacity: 0, y: 40 }}
  whileInView={{ opacity: 1, y: 0 }}
  viewport={{ once: true, margin: "-100px" }}
  transition={{ duration: 0.6, ease: "easeOut" }}
>
  内容
</motion.div>
  • 关键参数：
    • once: true — 动画只触发一次，避免来回滚动重复播放
    • margin: "-100px" — 元素进入视口 100px 后才触发，避免边缘突兀
    • ease: "easeOut" — 缓出曲线，自然减速感
  • 卡片悬浮发光效果：使用 Tailwind CSS 的 hover: 伪类 + transition + 自定义 shadow： 
    <div class="transition-all duration-300
     hover:border-blue-500/50
     hover:shadow-[0_0_30px_rgba(88,166,255,0.15)]">
  卡片内容
</div>
  • 自定义 Hook 封装：可将动画配置封装为 useScrollAnimation Hook，统一管理动画参数
  • 性能注意：Framer Motion 使用 GPU 加速的 transform 和 opacity 属性，不触发重排，性能优于直接操作 DOM
关键结论：Framer Motion 的 whileInView 是实现滚动动画的最简方案，无需监听 scroll 事件。卡片悬浮发光用 Tailwind 的 hover:shadow-[...] 任意值语法即可，无需额外 CSS 文件。动画性能的关键是只操作 transform 和 opacity。

DeepSeek Harness (dsh)：全插件化 Agent 框架架构解析

分类： AI · Agent 框架

问题描述： DeepSeek 开源的 Harness (dsh) 是什么？其架构设计有何特点？

回答要点

  • 项目定位：DeepSeek Harness（dsh）是 DeepSeek AI 开源的 Agent Harness 框架，目前处于 Developer Preview 阶段
  • 核心理念：一切皆插件（Everything is a plugin）——所有功能模块（LLM 调用、工具集成、UI 组件）均以插件形式加载
  • 底层框架：基于 Cordis 框架构建，Cordis 的设计理念源自论文 "A Programming Paradigm for Spatiotemporal Composability"
  • 运行方式：
    • NPM 直接运行：npx @deepseek-ai/dsh web（启动 Web UI，默认 http://127.0.0.1:3080）
    • 源码运行：git clone → pnpm install → pnpm run build → pnpm dsh web
  • 插件生态：插件仓库通过 dsh-plugin GitHub Topic 标记，社区可通过 GitHub Discussions 提交反馈
  • 注意事项：当前阶段迭代快速，存在兼容性破坏变更，不建议用于生产环境
  • 项目结构：包含完整的文档体系（README、CONTRIBUTING、BENCHMARK、THIRD_PARTY_NOTICES）、GitLab CI 配置、国际化支持（i18n YAML）
关键结论：DeepSeek Harness 采用"全插件化 + Cordis 时空可组合范式"的架构设计，区别于 LangChain 等传统 Agent 框架的硬编码方式。其核心创新在于 Cordis 的时空可组合性理论——插件可以在不同时间和空间维度自由组合。目前处于早期阶段，适合关注和实验但不适合生产使用。

Ollama Modelfile 配置：Qwen 3.5 关闭思考模式

分类： AI · 本地模型部署

问题描述： 如何通过 Ollama Modelfile 配置 Qwen 3.5 模型关闭 thinking 模式，加速推理？

回答要点

  • Modelfile 格式：Ollama 使用类似 Dockerfile 的声明式配置文件 Modelfile，定义模型来源和运行参数
  • 配置内容： 
    FROM qwen3.5:9B
PARAMETER think false
  • 指令说明：
    • FROM — 指定基础模型（此处为通义千问 3.5 9B 参数版本）
    • PARAMETER think false — 关闭模型的思考/推理链模式，直接输出答案
  • 使用方式： 
    # 创建自定义模型
ollama create qwen35-nothink -f Modelfile.qwen35nothink

# 运行模型
ollama run qwen35-nothink
  • 适用场景：关闭 thinking 模式适用于简单问答、代码补全等不需要复杂推理链的场景，可显著降低延迟和 token 消耗
  • 对比：开启 thinking 时模型会先输出 <think>...</think> 推理过程再给答案，适合数学推导、逻辑分析等复杂任务
关键结论：Ollama Modelfile 的 PARAMETER think false 可一键关闭 Qwen 3.5 的思考模式。对于不需要推理链的日常问答场景，关闭 thinking 可减少约 50-80% 的 token 输出量，显著降低推理延迟。建议根据任务复杂度动态选择是否开启。

RSS Feed 自动生成：从数据文件到 XML

分类： Other · 自动化工具

问题描述： 如何从项目的 TypeScript 数据文件自动生成 RSS Feed XML？

回答要点

  • 设计思路：编写 Node.js 脚本（CommonJS 格式），读取 src/data/ 下的文章数据文件，合并生成标准 RSS 2.0 XML
  • 数据源合并：支持多个数据源合并——如公众号文章（articles.ts）+ FAQ 知识库文章（articles-faq.ts），按日期排序取 Top N
  • 关键实现：
    • 使用 fs.writeFileSync 写入 public/feed.xml
    • RSS 2.0 标准字段：<channel>、<item>、<title>、<link>、<description>、<pubDate>
    • 日期格式：RFC 822 标准（如 Sun, 16 Aug 2026 20:00:00 +0800）
    • CDATA 包裹描述内容，避免 XML 转义问题
  • 集成到构建流程： 
    # package.json scripts
{
  "build": "node scripts/generate-rss.cjs && vite build"
}
  • 注意事项：XML 特殊字符（<、&、>、"、'）必须转义或用 CDATA 包裹
关键结论：RSS Feed 自动生成的核心是"数据文件 → Node.js 脚本 → XML"流水线。将 RSS 生成集成到 npm run build 流程中，确保每次构建都有最新内容。关键坑点：XML 特殊字符必须转义，日期必须用 RFC 822 格式，描述内容用 CDATA 包裹最安全。

跨仓库技术文章自动提取与整合

分类： Other · 自动化工具

问题描述： 如何从一个 Git 仓库（Technical-FAQ）自动提取文章列表并生成另一个仓库的 TypeScript 数据文件？

回答要点

  • 场景：Technical-FAQ 仓库（D:/workbuddyFile/Technical-FAQ/html/）按分类目录存储 HTML 文章，需要自动提取标题、摘要、日期、URL 并生成 portfolio 网站的 articles-faq.ts
  • 提取脚本设计：
    • 遍历 4 个分类目录：AI/、Communication/、Computer/、Other/
    • 解析每个 HTML 文件的 <title> 标签获取标题
    • 用正则去除 HTML 标签提取纯文本，取前 160 字符作为摘要
    • 从文件名提取日期（YYYY-MM-DD-*.html 格式）
    • URL 编码：encodeURIComponent 处理中文文件名
  • 摘要清洗：需要过滤导航面包屑、标题重复、来源元信息等噪声文本： 
    // 噪声模式过滤
const noisePatterns = [
  /^\s*[←←]?\s*返回[\s\S]{0,20}?(索引|目录)\s*/,
  /^\s*☰\s*(目录|导航)\s*/,
  /^\s*目录\s*/,
  /^\s*首页\s*/,
];
  • 输出格式：生成标准 TypeScript 数组，每条记录含 id、title、summary、date、url、category、source、tags 字段
  • 分类映射：目录名到中文标签的映射：AI→AI、Communication→通信网络、Computer→计算机基础、Other→其他
  • 排序策略：按日期降序排列，确保最新文章排在前面
  • URL 构造：文章链接指向 GitHub Pages 地址：https://slyum123.github.io/Technical-FAQ/html/<分类>/<文件名>.html
关键结论：跨仓库文章提取的核心是"目录遍历 → HTML 解析 → 文本清洗 → TS 生成"四步流水线。最大挑战是摘要清洗——HTML 文件中的导航、面包屑、元信息等噪声文本需要用正则模式过滤。文件名中包含中文时，URL 必须用 encodeURIComponent 编码。脚本设计为幂等可重复执行，每次运行覆盖生成结果。

技术知识点沉淀

Vite 构建工具核心优势

  • 开发阶段：利用浏览器原生 ESM，按需加载模块，启动时间与项目规模解耦（冷启动 <1s）
  • HMR 机制：基于 ESM 的 HMR，只需通知变更模块及其依赖链，不是全量刷新
  • 生产构建：基于 Rollup，支持 Tree-Shaking、代码分割、懒加载
  • 配置简洁：vite.config.ts 一个文件管理所有构建配置，无需 webpack 那样复杂的配置链

shadcn/ui vs 传统组件库

维度shadcn/ui传统组件库（Ant Design / MUI）
分发方式Copy-Paste（源码在项目内）NPM 包安装
定制性完全控制，直接修改源码受限于 API 和主题系统
包体积只包含使用的组件Tree-shaking 后仍可能较大
版本管理组件版本与项目一致需手动升级 NPM 包
样式方案Tailwind CSS 原生CSS-in-JS / Less / SCSS

Cordis 框架核心概念

  • 时空可组合性（Spatiotemporal Composability）：一种编程范式，允许组件在时间维度（生命周期）和空间维度（上下文隔离）上自由组合
  • 插件架构：每个插件是一个独立的可组合单元，通过服务注册和依赖注入实现松耦合
  • 与 DeepSeek Harness 的关系：dsh 基于 Cordis 构建，所有功能（LLM、工具、UI）均以 Cordis 插件形式存在
