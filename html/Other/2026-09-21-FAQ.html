Q1 TSP 的「功能切片微架构」如何颠覆传统多核 CMP？AI
问题描述

传统多核芯片（CMP）把「小可编程核」复制几十上百次，每个 tile 内含完整的取指/译码/执行/访存/写回五级流水，由硬件动态调度，通过片上网络互联。Groq《Think Fast》(ISCA 2020) 提出的 TSP 做了什么结构性反转？

回答要点
  • 不复制小核，而造一个巨型单处理器：把核心五级流水按功能拆开并重组成纵向切片（slice），局部功能同构、全局异构 — 与传统 CMP 的「局部异构、全局同构」正好相反。
  • 切片全集：ICU（指令控制与派发）、MEM（片上 SRAM 读写）、VXM（逐元素算术/激活）、MXM（稠密矩阵乘加，算力核心）、SXM（向量置换/路由）、C2C（芯片间收发 320 字节向量）。每个 slice 只支持自己角色的指令（如 MEM 只支持 Read）。
  • 物理组织：一个 functional slice 含 20 个 tile，每 tile 处理 16 元素 → 最大向量长度 320 元素（320 字节向量）。
  • 收益：数百功能单元共享一套被「展开」的指令流，大幅摊薄译码开销；邻近性 + 精简每操作指令数 + 高效数据流三者协同降低延迟。
关键结论：TSP 的本质是「按功能解聚合（disaggregate）而非按核复制」。它用单逻辑核心 + 数百功能单元 + 编译期静态调度，换掉了多核 + 运行时动态调度这一整套范式。
Q2 「指令流 × 数据流相遇」的执行机制是什么？编译器看到的是什么？AI
问题描述

TSP 区别于 GPU「SIMD + 动态调度」的核心机制是什么？运算究竟在什么时刻发生？

回答要点
  • 两条物理分离、编译期被安排「相遇」的流：指令流沿 slice 方向纵向传播；数据流（操作数流）作为流横向跨 slice 穿行。当一条指令与其被调度好的操作数流在某功能单元相遇时，运算执行 — 运算不是「调用」出来的，而是「被调度相遇」出来的，硬件不做任何运行时决策。
  • 编译器视角：144 个独立指令队列，每个队列维护一个逻辑时间（logical time）；生产者与消费者节拍不一致时，编译器插入 wait 或重复 nop 对齐。
  • ISA 暴露操作延迟与指令-操作数 skew，使调度做到 cycle-aware（时钟周期级精确）。
  • 编程模型：生产者-消费者流式模型，PE 通过流（stream）而非缓存/共享内存通信与同步；SRAM 放置、张量流时序与路由全部编译期决定。
关键结论：复杂度没有被消除，而是被从运行时硬件转移到编译期软件。这是 TSP 能保证「编译期可精确预测延迟」的直接原因，也是它与 CUDA 心智模型差异最大的地方。
Q3 TSP 的确定性（零方差延迟）从何而来？实测证据是什么？AI
问题描述

论文开篇指出传统架构三重困境：ALU 需近峰值利用率、运行时停顿不可推理、缓存/分支预测/预取器无法界定最坏情况延迟。TSP 如何破解？

回答要点
  • 手段：在硬件中移除全部「反应式（reactive）」元件 — 仲裁器（arbiter）、缓存（cache）、分支预测器、重排缓冲（ROB）、预取器。指令顺序完全由软件控制，底层硬件不能重排且必须在固定时间内完成。
  • 系统级后果：零方差延迟 → 低延迟 → batch-1 高吞吐 → 面向多样 SLA 的可预测性能 → 降低数据中心 TCO。
  • BERT 实证（《Answer Fast》）：4000 次推理平均延迟 128.9 µs，标准差仅 3.8 µs，P1 = 128.5 µs、P99 = 129.5 µs；唯一波动来源是 PCIe 重传，片上执行本身无抖动。
  • 可预测性量化（最强证据）：编译器部署前的延迟预估，仅比硬件实测长 1%。
  • 吞吐侧：ResNet50 batch-1 20.4K IPS（约 4× GPU）；BERT-base batch-1 ~130 µs（约 6× 同期 SOTA GPU）；首版 ASIC 计算密度 > 1 TOPS/mm²（25×29 mm、14nm、900 MHz）。
关键结论：在 SLA 严苛场景（实时推理、金融、自动驾驶），可预测的尾部延迟比平均吞吐更有价值。TSP 用「去反应式硬件」把最坏情况性能变成可界定的量 — 这是带缓存/乱序的 GPU 无法提供的。
Q4 2022 系统论文如何把单芯片扩展为万级 TSP 系统？AICommunication
问题描述

《A Software-defined Tensor Streaming Multiprocessor》(ISCA 2022) 解决了单芯片「大模型放不下 / 算力不够」的问题，具体机制是什么？

回答要点
  • TSP 身兼二职：既是 endpoint，又是交换机 — 无需外部网络设备即可搬移张量；软件控制网络避免动态链路竞争引入的延迟变化（回归确定性主线）。
  • 软件定义的 Dragonfly 拓扑：商用软件定义方法覆盖封装、路由、流控，提供通信与同步原语，构建 bandwidth-rich 的全局通信基底。
  • 全局内存：逻辑共享、物理分布的片上 SRAM — 每颗 TSP 贡献 220 MiB，容量仅受网络规模限制。
  • 规模：最多 10,440 颗 TSP、超 2 TB 全局内存、端到端系统延迟 < 3 µs；弹性支持训练与推理、数据并行与（流水式）模型并行。
关键结论：这一层把 TSP 从「单芯推理加速器」抬升为「可训练、可扩展的并行 ML 系统」，其「软件定义互连 + 分布式 SRAM 池」思路与今日 scale-up fabric（UALink / UB / CXL 内存池化）是同一条技术脉络。
Q5 TSP vs GPU 的核心差异，以及它的客观局限？AI

batch-1 推理高吞吐需大 batch 摊薄

局限（客观审视）：

  • 模型必须编译、覆盖受限：只有被编译器适配的模型能跑，自定义/微调架构无法直接部署，灵活性远逊 CUDA 生态。
  • SRAM 容量约束：单芯仅 ~220 MiB，超大模型必须跨多芯分片，系统复杂度与成本上升。
  • 训练生态弱：2020 论文聚焦推理，训练能力 2022 才系统论述，实践生态明显弱于 GPU。
  • 对比公平性：4×/6× 提速针对 batch-1 与特定模型；持续高并发批处理场景 GPU 利用率经济性或更优。
  • 大 die 工程风险：725 mm² 大芯片、约 185 W，面积/良率/散热挑战显著。
关键结论：TSP 的独特标签是 batch-1 推理的确定性与编译期可预测性，而非通用算力领先。行业认可佐证：据报道 NVIDIA 于 2025-12 以约 200 亿美元非独占授权 TSP/LPU 架构（具体条款以官方披露为准）。
Q6 SemaCredit 要解决 Scale-Up Fabric 中的什么「流控错配」？Communication
问题描述

Scale-Up 互连（UALink / UET / UB 等）正成为紧耦合 GPU 系统的内存访问基座，其流量绝非均匀字节流。现有传输层接收端 credit（UET receiver credit、Meta CTS、MRC）都以「字节」观测网络，会漏掉什么？

回答要点
  • 错配本质：字节计价的 credit 能保护链路缓冲与 HBM 流式流量，但无法表达两类「字节数与占用时间相差数量级」的完成路径资源 — ① Atomic 执行（固定成本、串行引擎）；② 响应注入（下游反向管线）。
  • 核心区分：字节队列问「有多少数据在途」，服务队列问「目标端还要忙多久」。对流式 HBM 两者近等价，对固定成本操作可差数量级。
  • 实测动机：RDCA(NSDI'23) 实测接收端内存带宽争用使 RDMA 吞吐下降约 15%；Harmonic(NSDI'24) 证明同包大小 verb 成本不同（ATOMIC ≈ 3× WRITE）；GPU Atomic 实测无争用 2.4–3.5 ns、争用时约 30 ns 地板（AMD 85–100 ns）— Atomic 服务既不是字节速率也不是常数。
  • 三类典型负载：AllReduce 形态（大块流式写 + 小归约 Atomic）、远端参数/KV/元数据读（小请求产生反向响应流量）、MoE dispatch（倾斜专家写压 HBM 分区）。
关键结论：现有机制都在回答「接收端要不要接」，没人回答「接收端容量应如何在 HBM 分区、Atomic 引擎、响应注入之间分配」。这就是 SemaCredit 的切入点。
Q7 需求向量 + 全有或全无准入 + 分阶段归还：机制如何运作？Communication
回答要点

需求向量分量（仅用端点已有字段，线上协议零改动）：

  • d_i,HBM_p = b_i / R_p — 字节约当；HBM 保留字节计数、不加固定服务惩罚（否则 MoE 形态被无谓压制）。
  • d_i,Atomic_e = t̂_atomic(op_i) — 按 opcode 查表的纳秒债务。
  • d_i,Response_j = t̂_0,j + b_i^resp / R_j — 固定注入开销 + 响应字节约当。

准入与归还：∀r (d_i,r > 0) 需满足 D_r + d_i,r ≤ W_r，一次全有或全无的向量预留（防止「一个命令拿走最后一份 HBM credit、另一个拿走最后一份响应 credit」的死锁面）；归还跟随接收端执行 — HBM credit 在内存访问后还、Atomic 在执行后还、响应 credit 在注入后还。

状态预算：10 个资源条目（160 B）+ 128 个在途命令扩展（2 KiB）≈ 2.2 KiB；准入可并行（每分量一条 add-and-compare + AND 归约），不在关键路径串行化。窗口下限钳制到最坏路径 RTT（1 µs），串行 Atomic 引擎取 4×RTT。

关键结论：归还时机消融证明了两种错误记账 — 「到达即还」使响应 P99 恶化 2.05×（下游无界）；「持有到端到端完成」使 P99 +6.4%、goodput −0.9%（把已完成的 HBM 工作与响应耦合）。分阶段归还是既保安全又最大化流水并行的唯一解。
Q8 为什么单一标量窗口不够？不可能性反例是什么？Communication
回答要点
  • 形式化反例：两个资源各安全窗口 W，两个操作需求为 (W, 0) 与 (0, W)。标量窗口 ≤ W 安全但无法并行放行两者（不 work-conserving）；标量窗口 2W 能放行该组合，但也会放行两个 (W, 0) 而击穿第一个资源（不安全）。故不存在同时满足逐资源安全与工作保持的固定标量。
  • 实验侧证（Scalar service，Harmonic 式归一化成本）：scale=4 时 Atomic P99 低 10%，但 HBM P99 高 37%、响应高 17%；scale=2 时 HBM P99 仍为 SemaCredit 的 1.82×。标量必须猜当前瓶颈，向量直接点名瓶颈。
  • 反应式基线（UET 风格 resource exhaustion + 重试）远劣于事前准入：SemaCredit 相对其 Atomic/响应 P99 低 50.1% / 72.1%，平均少 92 / 34 次重试，goodput +4.5% / +3.9%。
关键结论：这是全篇最强的理论支撑 — 向量准入不是工程优化偏好，而是由不可能性反例强制的必要性；且「事后禁用 + 重试」永远补不上「事前向量预留」的差距。

Q10 如何落地部署？模型误差下如何保持鲁棒？Communication
回答要点
  • 两种接口：① 显式 — 接收端广播不透明资源类 credit，发起端在命令上挂资源类掩码（接收端仍以自身译码为准，仅作准入提示）；② 隐式（评测采用） — 线上协议完全不变，目标端分类器从 opcode / 地址 / 长度 / 响应大小本地映射，不暴露物理分区 ID。
  • 可靠性组合规则：重传命令复用原预留；重复完成不归还 credit（用传输层操作 ID 判重）；准入只决定「何时进入」，序域（fence、write-then-notify）照常生效。
  • EWMA 自适应校准：m ← 0.9375·m + 0.0625·(t_obs / t̂)，逐资源一个乘子。50% 系统性低估时，静态版比字节基线差 9.2%，自适应版反转为好 6.1%；2× 高估时静态版 P99 好 22.7% 但 goodput 掉 8.2%，自适应把损失限到 2.0%。
  • 部署教训（反直觉）：零均值双峰波动下，静态均值成本反而更好 — EWMA 会被单个慢样本带偏。慢速校准治系统性偏差，勿逐操作追逐随机样本。
  • 边界：确定性模型仅隔离「接收端完成路径计费」一层，未覆盖 kernel 执行与产品微架构；后续路线为 trace 回放 → 自适应控制理论 → 周期级/RTL/FPGA（验证 2.2 KiB 逻辑估计的 SRAM/面积/功耗）→ 端到端训练步/token 延迟验证。
关键结论：对自研 scale-up 芯片最实用的一点是 — 该机制可在不改动线上协议的前提下纯接收端实现（隐式接口），且总状态量仅约 2.2 KiB；代价是需求估计必须准确，需配慢速 EWMA 校准而非逐操作自适应。

附：当日技术知识点沉淀

1. AI 加速器架构设计的两条正交路线

  • 反应式路径（GPU 主流）：缓存 + 乱序 + 分支预测 + 预取 + 仲裁 → 优化平均性能，但最坏情况不可界定。
  • 静态路径（TSP / 经典 VLIW / 部分 DSA）：移除全部反应式元件，把调度交编译器 → 零方差延迟、可界定最坏情况，代价是模型覆盖受限、编译门槛高。
  • 选型判据：SLA 尾部延迟敏感 → 静态；生态/通用性/训练 → 反应式。

2. Scale-Up 端点流控的三层计价对象

  • 字节（bytes） → 适合流式带宽资源（HBM 分区、链路缓冲）。
  • 服务时间（nanoseconds） → 适合固定成本/串行资源（Atomic 引擎）。
  • 固定开销 + 字节 → 适合反向管线（响应注入）。
  • 关键：计价单位必须匹配资源的占用度量；混用会造成数量级错配（字节计价对 Atomic 完全无效）。

3. Credit 归还时机的三条设计律

  • 到达即还 → 下游无界（响应 P99 恶化 2.05×）。
  • 端到端才还 → 独立资源被耦合（P99 +6.4%、goodput −0.9%）。
  • 按阶段归还（内存/Atomic/注入各自完成时） → 安全与流水并行兼得。
  • 窗口下限必须 ≥ 最坏路径 RTT，否则 credit 环喂不饱资源（Atomic 引擎取 4×RTT 以容忍投递波动）。

4. 自适应控制的适用边界

  • EWMA 校准对系统性偏差（估计模型结构性错误）有效：50% 低估下由 −9.2% 反转为 +6.1%。
  • 对零均值随机波动有害：会被单个慢样本带偏，静态均值反而更优。
  • 推论：先判别偏差性质（系统 vs 随机），再决定是否上自适应环。
