02 Groq LPU 是什么？与 GPU 相比有何根本差异？AI
问题描述

Groq LPU（Language Processing Unit）的定位是什么？它与传统 GPU 在设计哲学上有何本质不同？

回答要点
  • 定位差异：GPU 是通用并行计算处理器（训练+推理），LPU 是专为 LLM 推理（Inference）从第一性原理重新设计的专用加速芯片
  • 内存架构：GPU 用片外 HBM（~3.35 TB/s），LPU 用片上 SRAM（~80 TB/s），带宽高约 24 倍
  • 调度模型：GPU 运行时动态调度（硬件决定数据流），LPU 编译期静态调度（编译器提前排好每个时钟周期的操作）
  • 执行模型：GPU 有分支预测/乱序执行/缓存，LPU 去除所有反应式硬件组件，实现确定性执行
  • 命名历史：LPU 原名 TSP（Tensor Streaming Processor），后改名 LPU 以突出推理定位；创始人为 Google TPU 核心发明者 Jonathan Ross
关键结论：LPU 与 GPU 的根本差异不在于"更快"，而在于设计哲学的根本分歧——GPU 是"通用处理器被改去跑 AI"，LPU 是"只为把 LLM 推理跑到极致而生的专用芯片"。核心三角：片上 SRAM + 编译器静态调度 + 确定性单核数据流。
03 LPU 如何解决推理阶段的"内存墙"问题？AI
问题描述

大模型推理 Decode 阶段为何受限于内存带宽？Groq LPU 的片上 SRAM 方案如何打破这一瓶颈？

回答要点
  • 内存墙的本质：Decode 阶段每生成一个 Token 都需读全量模型权重，属 memory-bound 而非 compute-bound
  • GPU 瓶颈：70B 模型 FP8 约 70GB 权重，H100 HBM 带宽 ~3.35 TB/s，每 Token 搬运权重就耗数十毫秒
  • LPU 方案：权重常驻片上 SRAM（~230MB/芯），带宽 ~80 TB/s，同样权重搬运在微秒级完成
  • 带宽倍数：SRAM 带宽较 HBM 高约 24 倍（80 TB/s vs 3.35 TB/s）
  • 容量约束：SRAM 容量有限，超过单芯容量的模型需跨多芯分片（tensor/pipeline parallelism）
指标Groq LPUNVIDIA H100
内存类型片上 SRAM片外 HBM3
内存带宽~80 TB/s（LPX 150 TB/s）~3.35 TB/s
推理速度（70B）300-750+ tok/s100-150 tok/s
每 Token 能耗~1-3 J/tok~10-30 J/tok
关键结论：GPU 卡在"内存墙"上——算力远超带宽，大量时间花在等数据。LPU 把内存放到片上 SRAM，从物理层面消除了片外访存往返，是"拆墙"而非"翻墙"。代价是 SRAM 容量受限（单芯 ~230MB），需多芯分片处理大模型。
04 LPU 的确定性执行（Determinism）是如何实现的？有何工程价值？AI
问题描述

LPU 宣称"确定性执行、零抖动延迟"，这在硬件层面如何实现？对生产系统有何实际意义？

回答要点
  • 去除反应式硬件：无分支预测器、无仲裁器、无重排缓冲（ROB）、无缓存——这些是 GPU 延迟波动的根源
  • 编译期全静态调度：Groq 编译器在编译期分析整张计算图，生成确定性调度——每个 TSP 在每个时钟周期做什么都提前确定
  • VLIW + TISC：超长指令字（VLIW）+ 时序指令集计算机（TISC），指令执行顺序编译期确定，无运行时猜分支、无乱序执行
  • 144 个独立指令队列：编译期可见，通过逻辑时间对齐生产者与消费者（插入 wait/nop 实现节拍对齐）
  • 工程价值：P99 无尖峰抖动（vs GPU 随负载波动），首 Token 延迟 P50 < 300ms 且不随并发变化，利于生产级 SLA 保障
关键结论：确定性执行的核心是"把复杂度从硬件搬到编译期"——GPU 用昂贵的运行时动态调度硬件换取灵活性，LPU 用编译器的编译期分析换取零运行时决策开销。对金融交易机器人、实时语音 Agent 等延迟敏感场景，确定性比"平均快"更关键。

问题描述

LPU 采用"功能切片式微架构"（Functionally Sliced Microarchitecture），其内部结构如何组织？各功能单元的职责是什么？

回答要点
  • 组织方式：内存单元与向量/矩阵计算单元交错排布，利用深度学习负载固有的数据并行性
  • 功能切片：一个 slice 含 20 个 tile，每个 tile 处理 16 个元素，最大向量长度 320 元素
  • 片上 SRAM：~230 MB，不是缓存而是加速器本地工作存储，由编译器全局寻址调度

07 Groq LPU 的软件栈（GroqWare）包含哪些核心组件？Computer
问题描述

GroqWare 软件套件如何支撑从模型导入到部署运行的全流程？各组件的角色是什么？

回答要点
  • Groq Compiler（基于 MLIR）：与 TSP 架构协同设计，编译流程：模型导入 → 布局与向量化 → 多芯分片 → 映射到 ISA → 活状态规划 → 指令调度 → 汇编
  • GroqFlow 自动化工具链：一行 PyTorch/TensorFlow 代码即可把模型自动导入、转换、优化并运行——开发者"零摩擦"上 LPU 的关键
  • Groq API & 运行时：提供底层细粒度 API + 高级 REST API，官方 Python 客户端 pip install groq，OpenAI 兼容
  • GroqView 性能可视化：编译期可视化芯片计算与内存使用，Performance Estimator 可在编译前预测性能
  • 框架支持：PyTorch、TensorFlow、ONNX；社区集成 LangChain、Vercel AI SDK、LiteLLM、Gradio
关键结论：Groq 的"软件定义硬件"理念意味着编译器与芯片架构深度协同设计——编译器承担了 GPU 由硬件运行时处理的调度复杂度。GroqFlow 是降低开发者门槛的关键入口，OpenAI 兼容 API 使迁移成本接近零（改一行 base_url）。
