总览

DeepSeek-V3 是一个 671B 参数的 Mixture-of-Experts (MoE) 语言模型，每个 token 仅激活 37B 参数。它在架构上继承 DeepSeek-V2 的 MLA 注意力和 DeepSeekMoE 架构，并引入了无辅助损失负载均衡和多 Token 预测两项创新。整个训练仅消耗 2.788M H800 GPU 小时，训练过程零回滚、零不可恢复 loss spike。

01-架构介绍 / 总体架构

架构全景

DeepSeek-V3 采用 Transformer 解码器架构，核心创新集中在三个层面：

  1. 注意力层：Multi-head Latent Attention (MLA) — 通过低秩压缩 KV 缓存，将每 token 的 KV 缓存从 40,960 维降至 576 维（压缩率 98.6%）
  2. 前馈层：DeepSeekMoE — 256 个路由专家 + 2 个共享专家，每 token 仅激活 8 个路由专家，配合无辅助损失的动态偏置负载均衡
  3. 训练目标：Multi-Token Prediction (MTP) — 预测未来 D 个 token，增强训练信号密度，推理时可丢弃或用于投机解码

层级结构

DeepSeek-V3 共 61 层 Transformer Block。前 3 层（Layer 0-2）使用密集 MLP 前馈网络，后 58 层（Layer 3-60）使用 MoE 稀疏前馈网络。这种设计使得早期层能学习通用特征表示，后期层通过专家路由实现容量扩展。

01-架构介绍 / MLA 多头潜在注意力

核心思想

MLA (Multi-head Latent Attention) 通过低秩投影压缩 Key-Value 对，将 KV 缓存从传统的 n_heads × (d_k + d_v) 维降至 kv_lora_rank + qk_rope_head_dim 维。在 671B 模型中，这意味着每 token 的 KV 缓存从 40,960 维降至 576 维——压缩率 98.6%。

架构设计

MLA 采用混合位置编码策略，将 Query 和 Key 分解为两个分量：

  • NOPE 分量 (Non-Positional)：不包含位置信息，用于内容匹配
  • ROPE 分量 (Rotary Positional Embedding)：使用旋转位置编码，捕捉位置信息

无辅助损失负载均衡

传统 MoE 通过辅助损失函数强制负载均衡，但这会干扰模型主目标的梯度。DeepSeek-V3 创新性地采用动态偏置项策略：

Auxiliary-Loss-Free Load Balancing: 无辅助损失负载均衡（动态偏置机制） ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 传统 MoE（带辅助损失）： 总损失 L_total = L_主损失 + α × L_辅助损失 辅助损失强制负载均衡，但会污染主任务梯度！ DeepSeek-V3（无辅助损失）： 总损失 L_total = L_主损失（+ 极小的序列级平衡损失） 带偏置的路由： 亲和度分数 s_i = Sigmoid(u_t^T × e_i) 最终门控 g_i = s_i（当 s_i + b_i 在 Top-K 内，否则为 0） b_i = 动态偏置项（不进入梯度计算路径！） 偏置更新规则（每个训练步）： +---------------------------------------------+ | 若专家 i 过载： b_i -= γ （降低被选中概率）| | 若专家 i 欠载： b_i += γ （提高被选中概率）| +---------------------------------------------+ │ ▼ 关键洞察：偏置调整路由，但绝不进入损失函数梯度， 主目标函数保持纯净，不被负载均衡干扰！ 辅助安全网（极小权重）： 序列级平衡损失 L_bal = α × Σ(各专家负载 / N) α 非常小，仅作为兜底防止极端失衡

路由机制

DeepSeek-V3 使用 Sigmoid 评分函数 + 组路由限制（Node-Limited Routing）。256 个专家分为 8 组，每 token 从受限组中选择 Top-K 专家。这种设计限制了跨节点通信开销——因为每个 GPU 节点承载一组专家（EP=64，8 节点 × 8 GPU/节点 = 64 GPU，每组 32 专家）。

MoE Routing Flow (Per Token): MoE 路由流程（单个 Token 视角） ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 步骤 1：计算亲和度分数 u_t（Token 隐状态，维度 7168） s_i = Sigmoid(u_t^T × e_i) 对 i = 1..256 （e_i = 门控权重第 i 行，形状 [7168]） 步骤 2：叠加动态偏置 s_i' = s_i + b_i 步骤 3：组受限 Top-K 选择 256 专家 = 8 组 × 32 专家 受限组数 = 1（只从得分最高的 1 个组内选） 在允许的组内按 s_i' 选出 Top-8 专家 步骤 4：归一化权重 g_i = s_i / Σ(被选中专家的 s_j) （对选中专家） g_i = 0 （对未选中专家） 步骤 5：专家计算 输出 = Σ(g_i × Expert_i(u_t)) + 共享专家输出(u_t) 其中 Expert_i(x) = w2( silu(w1(x)) × w3(x) ) 共享专家 = 2 个始终激活的 MLP

01-架构介绍 / 多 Token 预测 (MTP)

核心思想

MTP 在训练时不仅预测下一个 token，还顺序预测未来 D 个 token。这增加了训练信号密度，让模型学会"提前规划"其表示。推理时 MTP 模块可丢弃（不影响主模型性能），也可用于投机解码加速推理。

01-架构介绍 / FP8 混合精度

概述

DeepSeek-V3 是首个在超大规模模型上验证 FP8 混合精度训练可行性的模型。通过 FP8 计算和存储，训练速度显著提升，GPU 内存使用大幅降低，且相对于 BF16 基线的损失误差低于 0.25%。

FP8 数据格式

采用 E4M3 格式（4 位指数，3 位尾数），优先尾数精度而非指数范围。所有 FP8 张量统一使用此格式。

01-架构介绍 / DualPipe 并行调度

设计动机

MoE 架构的跨节点 All-to-All 通信开销巨大（计算通信比接近 1:1）。DualPipe 算法通过将前向和后向计算分块，与通信重叠执行，实现接近零的 All-to-All 通信开销。

DualPipe 详细展开：为什么能隐藏通信开销

1. 传统流水线的气泡来源

在 16 路流水线并行（PP16）下，一个 micro-batch 需要依次经过 16 个 stage。反向传播时，梯度需要从最后一段传回第一段。在两段之间，GPU 必须等待前一个 stage 完成，产生流水线气泡（pipeline bubble）。

设每个前向分块耗时 T_f，每个反向分块耗时 T_b，通信耗时 T_c
传统 1F1B 气泡占比 ≈ (PP - 1) / (micro_batches × (T_f + T_b))

当 micro-batch 数量不够大时，气泡占比可达 30%-50%。

2. DualPipe 的双向流动

DualPipe 将每个 stage 的前向和反向进一步拆分为两个子块（a/b），并让前向从流水线左侧进入、反向从右侧进入。这样同一时刻每个 GPU 上既有前向又有反向，且通信与计算在不同 SM 上重叠：

GPU0: [F0a+C][F0b+C][B0a+C][B0b+C]
GPU1: [F1a+C][F1b+C][B1a+C][B1b+C]
GPU2: [B2a+C][B2b+C][F2a+C][F2b+C]
GPU3: [B3a+C][B3b+C][F3a+C][F3b+C]

C = All-to-All（MoE 分发/回收）+ 流水线点对点传输
| = 计算与通信在同一 GPU 的不同 SM 上并行

3. SM 分配

H800 每张卡约 132 个 SM。DeepSeek 定制通信内核只占用约 20 个 SM，其余约 112 个 SM 同时运行 GEMM：

通信 SM ≈ 20 个  → 负责 IB/NVLink 上的 All-to-All
计算 SM ≈ 112 个 → 负责 FP8 GEMM、Attention 等

4. 带宽自适应

定制内核同时感知两种网络拓扑：

  • 节点内：NVLink 160 GB/s，延迟低，可走大消息
  • 跨节点：InfiniBand 50 GB/s，延迟高，需合并小消息

内核会根据目标专家所在的物理位置，选择最短、最宽的路径发送 token。

5. 结果

  • 流水线气泡：几乎为零
  • All-to-All 通信开销：几乎为零（被计算重叠）
  • GPU 利用率：接近 100%
关键洞见：DualPipe 不是减少通信量，而是把通信“藏”在计算后面。只要计算时间 ≥ 通信时间，通信就不出现在关键路径上。

MLA 数值示例：KV 缓存压缩的真实计算

以下用 671B 模型参数，对一个 batch=1、序列长度 4096 的 prompt 做完整估算，直观对比标准 MHA 与 MLA Absorb 的内存占用。

1. 标准 Multi-Head Attention（无压缩）

  • 注意力头数 n_heads = 128
  • 每个头的 K 维度 = 192，V 维度 = 128
  • 每 token 每层 K 缓存 = 128 × 192 = 24,576 维
  • 每 token 每层 V 缓存 = 128 × 128 = 16,384 维
  • 每 token 每层 KV 缓存 = 24,576 + 16,384 = 40,960 维

序列长度 4096、BF16（2 字节）时：

单层 KV 缓存 = 4096 × 40960 × 2 B = 335,544,320 B ≈ 336 MB
61 层总缓存  = 336 MB × 61 ≈ 20.5 GB

2. MLA Absorb 模式

  • 压缩潜在表示 kv 维度 = 512
  • 位置编码分量 pe 维度 = 64
  • 每 token 每层缓存 = 512 + 64 = 576 维

同样 4096 序列、BF16：

单层 KV 缓存 = 4096 × 576 × 2 B = 4,718,592 B ≈ 4.7 MB
61 层总缓存  = 4.7 MB × 61 ≈ 288 MB

3. 压缩比

压缩比 = 20480 MB / 288 MB ≈ 71 倍
每 token 压缩比 = 40960 / 576 ≈ 71.1 倍
结论：在 4K 上下文下，MLA Absorb 将 KV 缓存从约 20.5 GB 降至 288 MB，使得单 batch 即可轻松装入显存；扩展到 128K 上下文时，标准 MHA 需要约 655 GB，而 MLA 仅需约 9.2 GB。

Gate 工作流程

Gate Routing Mechanism: Gate 门控路由机制 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 输入：x（批大小×序列长度, 维度 7168） 步骤 1：计算分数 分数 = Sigmoid(x @ 门控权重^T) # 形状 (N, 256) # 门控权重形状：[256, 7168]，即 256 个专家中心向量 步骤 2：组受限选择（Node-Limited Routing） # 256 专家 = 8 组 × 32 专家 # 受限组数 = 1（只从得分最高的 1 个组内选） # 作用：限制跨节点通信量！ +-------------------------------------------+ | 组 0 | 组 1 | ... | 组 7 | | 专家0-31| 专家32-63| ... | 专家224-255 | +-------------------------------------------+ │ │ │ 先选出得分最高的 1 个组 │ 再从选中的组内取 Top-8 专家 步骤 3：归一化权重 # 对 Sigmoid：选完再归一化 权重 = 分数[选中] / Σ(分数[选中]) 权重 ×= 路由缩放系数 2.5 输出： - 专家索引 indices：(N, 8) 选中的专家 ID - 路由权重 weights：(N, 8) 各选中专家的权重

负载均衡偏置项

偏置项 b_i 是一个长度为 256 的向量，不参与梯度计算。每个训练步骤后，根据每个专家的实际负载动态调整：

  • 专家过载 → b_i -= γ（降低偏置，减少被选中概率）
  • 专家欠载 → b_i += γ（增加偏置，提高被选中概率）

此外还有一个极小权重的序列级平衡损失 L_bal = α × Σ(load_i / N) 作为安全网。

MoE 路由数值示例：一个 Token 如何被分配专家

假设某 token 经过 ffn_norm 后得到隐藏状态 x（1×7168），门控权重 weight 形状为 [256, 7168]。下面给出完整计算过程。

步骤 1：计算 Sigmoid 分数

logits = x @ weight.t()   # 形状 (1, 256)
scores = Sigmoid(logits)  # 每个值在 (0, 1) 之间

为便于说明，假设前 16 个专家的 Sigmoid 分数如下（其余专家分数均较低）：

专家编号0123…3031
分数0.120.350.080.21…0.180.09

步骤 2：叠加动态偏置

当前训练步中，专家 0、2、31 略过载，偏置被调低；专家 1、3、30 略欠载，偏置被调高。例如：

scores'[0]  = 0.12 - 0.02 = 0.10
scores'[1]  = 0.35 + 0.03 = 0.38
scores'[2]  = 0.08 - 0.01 = 0.07
scores'[3]  = 0.21 + 0.02 = 0.23
scores'[30] = 0.18 + 0.02 = 0.20
scores'[31] = 0.09 - 0.02 = 0.07

步骤 3：组受限 Top-K 选择

256 个专家分成 8 组，每组 32 个。本例中专家 0-31 属于第 0 组。由于 n_limited_groups=1，系统只在得分最高的那一组内选 Top-8。

组内候选 = {0,1,2,...,31}
按 scores' 排序后 Top-8 = [1, 3, 30, 0, 7, 15, 22, 5]

步骤 4：归一化并缩放

提取这 8 个专家的原始 Sigmoid 分数（不加偏置），归一化后乘以 route_scale=2.5：

原始分数 = [0.35, 0.21, 0.18, 0.12, 0.11, 0.10, 0.09, 0.08]
求和     = 1.24
归一化   = [0.282, 0.169, 0.145, 0.097, 0.089, 0.081, 0.073, 0.065]
×2.5 后  = [0.705, 0.423, 0.363, 0.242, 0.222, 0.202, 0.182, 0.162]

步骤 5：专家计算与加权求和

expert_out = 0.705×Expert_1(x) + 0.423×Expert_3(x) + ... + 0.162×Expert_5(x)
shared_out = MLP_shared(x)      # 2 个共享专家始终激活
y = expert_out + shared_out
关键观察：动态偏置只影响“选谁”，不参与梯度；归一化时使用的仍是原始 Sigmoid 分数。这样既保证了负载均衡，又不会污染主损失梯度。

MTP 训练示例：多 Token 预测如何增加监督信号

假设输入文本为 "深度学习 是 未来 技术"，分词后得到 token 序列：

t_1 = [深], t_2 = [度], t_3 = [学], t_4 = [习], t_5 = [是], t_6 = [未], t_7 = [来], t_8 = [技], t_9 = [术]

主模型监督信号

主模型在位置 1 看到 [深]，预测位置 2 的 [度]；看到 [深, 度] 预测 [学]，依此类推。每个位置只产生一个交叉熵损失：

L_main = CE(P(t_2)|t_1) + CE(P(t_3)|t_1,t_2) + ... + CE(P(t_9)|t_1..t_8)

MTP 模块 1 的监督信号

MTP1 利用主模型在位置 1 的隐藏状态 h_1 和真实 token t_2 的嵌入，预测 t_3：

输入 = concat( h_1, emb(t_2) )  # 形状 (1, 2×7168)
输出 = MTP_Block( 拼接投影(输入) )
P_MTP1(t_3) = OutputHead( RMSNorm(输出) )
L_MTP1 = CE( P_MTP1(t_3), t_3 )

MTP 模块 2 的监督信号（若 D=2）

输入 = concat( h'_1, emb(t_3) )  # h'_1 是 MTP1 的输出隐藏状态
P_MTP2(t_4) = OutputHead( RMSNorm( MTP_Block(输入) ) )
L_MTP2 = CE( P_MTP2(t_4), t_4 )

总损失

DeepSeek-V3 实际使用 D=1，因此总损失为：

L_total = L_main + λ × L_MTP1    # λ 为 MTP 损失权重

若 D=2，则：

L_total = L_main + (λ/2) × (L_MTP1 + L_MTP2)
效果：每个训练 token 除了预测下一个 token，还要预测更远的 token，迫使模型学习更稳定的中间表示。论文指出即使 D=1，也能显著提升主模型性能；推理时若不需要投机解码，可直接移除 MTP 模块。

组件定位

量化流程

FP8 Quantization Pipeline: FP8 量化流水线 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 权重存储（离线，检查点阶段）： 原始权重 W（FP32/BF16，形状 [输出, 输入]） │ ▼ 128×128 块级量化 │ ▼ W_fp8（FP8 E4M3）+ 缩放因子 scale（FP32，[输出/128, 输入/128]） 运行时前向（每个 Linear 层内部）： 激活值 x（BF16，形状 [N, 输入]） │ ▼ act_quant(x) 按 1×128 块量化 │ ▼ x_fp8（FP8 E4M3）+ x_scale（FP32，[N, 输入/128]） │ ▼ fp8_gemm(x_fp8, W_fp8, x_scale, W_scale) │ │ 内部：FP8 矩阵乘在 Tensor Core 上执行 │ 每 Nc=128 个元素将累加提升到 FP32 │ ▼ 输出（BF16，形状 [N, 输出]） [注意] 嵌入层、注意力分数、门控路由 → 走 BF16/FP32 路径 （用 weight_dequant() 把 FP8 权重转回 BF16）

FP8 E4M3 量化数值示例

FP8 E4M3 用 1 位符号、4 位指数、3 位尾数，可表示的最大值约为 448.0，最小正规格数约为 0.00195。下面以激活值的一个 1×128 块为例。

1. 计算缩放因子

假设该块内 128 个 BF16 激活值为：

x = [0.5, -1.2, 3.4, -0.8, ..., 2.1]   # 共 128 个数

取绝对值最大值：

amax = max(|x_i|) = 3.4
scale = amax / 448.0 = 3.4 / 448.0 ≈ 0.00759

2. 量化到 FP8

x_fp8_i = round( x_i / scale )
# 例如 3.4  -> round(3.4 / 0.00759) = round(448) = 448（最大可表示值）
#     -1.2 -> round(-1.2 / 0.00759) = round(-158) = -158

FP8 张量只保存整数索引 [-448, 448]，实际值需要与 scale 相乘还原。

3. 反量化还原

x_hat_i = x_fp8_i × scale
# 3.4  -> 448 × 0.00759 = 3.40032  ≈ 3.4（误差 0.009%）
# -1.2 -> -158 × 0.00759 = -1.19922 ≈ -1.2（误差 0.065%）

4. 矩阵乘法中的累加精度

FP8 GEMM 在 Tensor Core 上计算，但每累加 128 个乘积后提升到 FP32：

acc_fp32 += Σ_{k=0}^{127} x_fp8[k] × W_fp8[k] × scale_x × scale_W
# 每 128 个元素做一次 FP32 累加，避免多次小量叠加导致精度崩溃

5. 权重块级量化（128×128）

权重按 128×128 的块独立量化。例如一个 7168×7168 的权重矩阵被划分为：

(7168/128) × (7168/128) = 56 × 56 = 3136 个块
每个块有自己的 scale（FP32）

块级量化比全局量化对异常值更鲁棒：某个块中出现大权重只影响该块的 scale，不会压低其他块的精度。

精度验证：论文报告 FP8 训练相对 BF16 基线的损失误差小于 0.25%。这得益于 (1) 细粒度块级量化，(2) 敏感操作保留 BF16/FP32，(3) 每 128 元素 FP32 累加。

ParallelEmbedding — 词表并行嵌入

class ParallelEmbedding(nn.Module):
    def __init__(self, vocab_size, dim):
        super().__init__()
        # 将词表按 world_size 切分，每个 rank 只存储部分词嵌入
        part = vocab_size // world_size
        self.vocab_start = rank * part
        self.vocab_end = self.vocab_start + part
        self.weight = nn.Parameter(torch.empty(part, dim))

    def forward(self, x):
        # 对超出本 rank 词表范围的 token 填零
        mask = (x < self.vocab_start) | (x >= self.vocab_end)
        x_clamped = x.clamp(self.vocab_start, self.vocab_end - 1)
        # 查表
        out = F.embedding(x_clamped - self.vocab_start, self.weight)
        out[mask] = 0
        # 跨 rank 汇总
        if world_size > 1:
            dist.all_reduce(out)
        return out

Linear — 带 FP8 量化的线性层

class Linear(nn.Module):
    def __init__(self, in_features, out_features, bias=False, dtype=None):
        super().__init__()
        self.weight = nn.Parameter(torch.empty(out_features, in_features))
        # FP8 量化: 存储缩放因子
        if dtype == "fp8":
            self.scale = nn.Parameter(torch.ones(
                (out_features + 127) // 128,
                (in_features + 127) // 128
            ), requires_grad=False)
        self.in_features = in_features
        self.out_features = out_features

    def forward(self, x):
        return linear(x, self.weight, self.scale)

def linear(x, weight, scale=None):
    # 如果权重量化 (element_size == 1, 即 FP8)
    if weight.element_size() == 1:
        if gemm_impl == "bf16":
            # BF16 模式: 先反量化再做标准 matmul
            w = weight_dequant(weight, scale)
            return x @ w.t()
        else:
            # FP8 模式: 激活量化 + FP8 GEMM
            x_fp8, x_scale = act_quant(x)
            return fp8_gemm(x_fp8, weight, x_scale, scale)
    else:
        # BF16 权重: 直接 matmul
        return x @ weight.t()

ColumnParallelLinear / RowParallelLinear

class ColumnParallelLinear(Linear):
    # 列并行: 输出维度按 world_size 切分
    # 每个 rank 只计算 part_out_features = out_features // world_size
    # 不需要通信, 后续 RowParallelLinear 会做 all_reduce 补偿
    def __init__(self, in_features, out_features):
        part_out = out_features // world_size
        super().__init__(in_features, part_out)

class RowParallelLinear(Linear):
    # 行并行: 输入维度按 world_size 切分
    # 每个 rank 只处理 part_in_features = in_features // world_size
    # 输出需要 all_reduce 聚合
    def __init__(self, in_features, out_features):
        part_in = in_features // world_size
        super().__init__(part_in, out_features)

    def forward(self, x):
        out = super().forward(x)
        if world_size > 1:
            dist.all_reduce(out)
        return out

RMSNorm

class RMSNorm(nn.Module):
    def __init__(self, dim, eps=1e-6):
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))

    def forward(self, x):
        return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps) * self.weight

class MLA(nn.Module):
    def __init__(self, args: ModelArgs):
        super().__init__()
        self.dim = args.dim                    # 7168
        self.n_heads = args.n_heads            # 128
        self.n_local_heads = args.n_heads // world_size  # 16 (8 GPU)
        self.q_lora_rank = args.q_lora_rank    # 1536
        self.kv_lora_rank = args.kv_lora_rank  # 512
        self.qk_nope_head_dim = args.qk_nope_head_dim  # 128
        self.qk_rope_head_dim = args.qk_rope_head_dim  # 64
        self.qk_head_dim = self.qk_nope_head_dim + self.qk_rope_head_dim  # 192
        self.v_head_dim = args.v_head_dim      # 128

        # Query 投影: 如果 q_lora_rank > 0 使用 LoRA 压缩
        if self.q_lora_rank == 0:
            self.wq = ColumnParallelLinear(self.dim, self.n_heads * self.qk_head_dim)
        else:
            self.wq_a = Linear(self.dim, self.q_lora_rank)           # 下投影 7168->1536
            self.q_norm = RMSNorm(self.q_lora_rank)
            self.wq_b = ColumnParallelLinear(self.q_lora_rank, self.n_heads * self.qk_head_dim)

        # KV 投影: 总是使用 LoRA 压缩
        self.wkv_a = Linear(self.dim, self.kv_lora_rank + self.qk_rope_head_dim)  # 7168->576
        self.kv_norm = RMSNorm(self.kv_lora_rank)
        self.wkv_b = ColumnParallelLinear(
            self.kv_lora_rank,
            self.n_heads * (self.qk_nope_head_dim + self.v_head_dim)  # 512->128*256
        )
        self.wo = RowParallelLinear(self.n_heads * self.v_head_dim, self.dim)

        self.softmax_scale = self.qk_head_dim ** -0.5
        # YaRN 长上下文缩放
        if args.max_seq_len > args.original_seq_len:
            mscale = yarn_get_mscale(args.rope_factor, args.beta_fast)
            self.softmax_scale *= mscale

        # 缓存: 两种模式
        if attn_impl == "naive":
            # 完整 K/V 缓存
            self.register_buffer("k_cache", torch.zeros(max_batch, max_seq, n_local_heads, qk_head_dim))
            self.register_buffer("v_cache", torch.zeros(max_batch, max_seq, n_local_heads, v_head_dim))
        elif attn_impl == "absorb":
            # 压缩 KV 缓存 (默认, 节省 98.6% 内存)
            self.register_buffer("kv_cache", torch.zeros(max_batch, max_seq, kv_lora_rank))
            self.register_buffer("pe_cache", torch.zeros(max_batch, max_seq, qk_rope_head_dim))

前向传播 (forward) — Naive 模式

def forward(self, x, start_pos, freqs_cis, mask=None):
    bsz, seqlen, _ = x.size()
    end_pos = start_pos + seqlen

    # === Query 路径 ===
    if self.q_lora_rank > 0:
        q = self.wq_b(self.q_norm(self.wq_a(x)))  # 7168->1536->norm->128*192
    else:
        q = self.wq(x)
    q = q.view(bsz, seqlen, self.n_local_heads, self.qk_head_dim)

    # 分离 NOPE 和 ROPE 分量
    q_nope, q_pe = torch.split(q, [self.qk_nope_head_dim, self.qk_rope_head_dim], dim=-1)
    q_pe = apply_rotary_emb(q_pe, freqs_cis)

    # === KV 路径 ===
    kv = self.wkv_a(x)                          # 7168->576
    kv, k_pe = torch.split(kv, [self.kv_lora_rank, self.qk_rope_head_dim], dim=-1)
    k_pe = apply_rotary_emb(k_pe.unsqueeze(2), freqs_cis)

    # 上投影到完整 K, V
    kv = self.kv_norm(kv)
    k = self.wkv_b(kv)                         # 512->128*256
    k = k.view(bsz, seqlen, self.n_local_heads, self.qk_nope_head_dim + self.v_head_dim)
    k_nope, v = torch.split(k, [self.qk_nope_head_dim, self.v_head_dim], dim=-1)

    # 拼接完整 Key (NOPE + ROPE)
    k = torch.cat([k_nope, k_pe.expand(-1, -1, self.n_local_heads, -1)], dim=-1)

    # 更新缓存
    self.k_cache[:bsz, start_pos:end_pos] = k
    self.v_cache[:bsz, start_pos:end_pos] = v

    # 注意力计算
    scores = torch.einsum("bshd,bthd->bsht", q, self.k_cache[:bsz, :end_pos])
    scores *= self.softmax_scale
    if mask is not None:
        scores += mask
    scores = scores.softmax(dim=-1)
    output = torch.einsum("bsht,bthd->bshd", scores, self.v_cache[:bsz, :end_pos])

    return self.wo(output.flatten(2))

前向传播 (forward) — Absorb 模式（默认，推理优化）

def forward(self, x, start_pos, freqs_cis, mask=None):
    bsz, seqlen, _ = x.size()
    end_pos = start_pos + seqlen

    # === Query 路径 (同 naive) ===
    q = self.wq_b(self.q_norm(self.wq_a(x)))
    q = q.view(bsz, seqlen, self.n_local_heads, self.qk_head_dim)
    q_nope, q_pe = torch.split(q, [self.qk_nope_head_dim, self.qk_rope_head_dim], dim=-1)
    q_pe = apply_rotary_emb(q_pe, freqs_cis)

    # === KV 路径 (关键差异: 不上投影!) ===
    kv = self.wkv_a(x)                          # 7168->576
    kv, k_pe = torch.split(kv, [self.kv_lora_rank, self.qk_rope_head_dim], dim=-1)
    k_pe = apply_rotary_emb(k_pe.unsqueeze(2), freqs_cis)

    # 缓存压缩表示 (512维 + 64维), 而非完整的 K/V!
    self.kv_cache[:bsz, start_pos:end_pos] = self.kv_norm(kv)
    self.pe_cache[:bsz, start_pos:end_pos] = k_pe.squeeze(2)

    # === "吸收" wkv_b 到注意力计算 ===
    # 将 wkv_b 权重 reshape 为 [n_local_heads, -1, kv_lora_rank]
    wkv_b_weight = self.wkv_b.weight  # [n_local_heads * 256, 512]
    wkv_b_weight = wkv_b_weight.view(self.n_local_heads, -1, self.kv_lora_rank)

    # 将 q_nope 投影到 kv_lora_rank 空间 (吸收 wkv_b 的 K 部分)
    q_nope_c = torch.einsum("bshd,hdc->bshc",
                          q_nope, wkv_b_weight[:, :self.qk_nope_head_dim])

    # 注意力: 分别计算 NOPE 和 ROPE 分量
    scores = (torch.einsum("bshc,btc->bsht", q_nope_c, self.kv_cache[:bsz, :end_pos])
              + torch.einsum("bshr,btr->bsht", q_pe, self.pe_cache[:bsz, :end_pos]))
    scores *= self.softmax_scale
    if mask is not None:
        scores += mask
    scores = scores.softmax(dim=-1)

    # 注意力输出在压缩空间, 再通过 wkv_b 的 V 部分投影回来
    x = torch.einsum("bsht,btc->bshc", scores, self.kv_cache[:bsz, :end_pos])
    x = torch.einsum("bshc,hdc->bshd", x, wkv_b_weight[:, -self.v_head_dim:])

    return self.wo(x.flatten(2))
Absorb 模式的核心优化：Naive 模式缓存 128×(192+128)=40,960 维/token，Absorb 模式只缓存 512+64=576 维/token。wkv_b 矩阵被"吸收"到 attention 计算中，不需要预先展开 K/V，从而实现 98.6% 的缓存压缩。

MLP — 密集前馈网络（也用作共享专家）

class MLP(nn.Module):
    def __init__(self, dim, inter_dim):
        self.w1 = ColumnParallelLinear(dim, inter_dim)    # gate projection
        self.w2 = RowParallelLinear(inter_dim, dim)       # down projection
        self.w3 = ColumnParallelLinear(dim, inter_dim)    # up projection

    def forward(self, x):
        return self.w2(F.silu(self.w1(x)) * self.w3(x))

Gate — MoE 门控路由

class Gate(nn.Module):
    def __init__(self, args):
        self.weight = nn.Parameter(torch.empty(args.n_routed_experts, args.dim))
        # 256 x 7168 的路由权重矩阵
        if args.n_expert_groups > 1:
            # 组路由参数
            self.n_expert_groups = args.n_expert_groups  # 8
            self.n_limited_groups = args.n_limited_groups  # 1
        self.score_func = args.score_func      # "sigmoid"
        self.route_scale = args.route_scale    # 2.5
        self.topk = args.n_activated_experts   # 8

    def forward(self, x):
        # Step 1: 计算亲和度分数
        scores = x @ self.weight.t()         # (N, 256)
        if self.score_func == "softmax":
            scores = scores.softmax(dim=-1)
        else:  # "sigmoid"
            scores = scores.sigmoid()

        # Step 2: 组限制选择 (Node-Limited Routing)
        if self.n_expert_groups > 1:
            # 将 256 专家分为 8 组, 每组 32 个
            group_scores = scores.view(x.size(0), self.n_expert_groups, -1).max(dim=-1)
            # 选出 Top-1 组
            group_idx = torch.topk(group_scores, self.n_limited_groups, dim=-1)[1]
            # 构造组掩码
            group_mask = torch.zeros_like(group_scores)
            group_mask.scatter_(1, group_idx, 1)
            # 屏蔽非选中组的专家
            scores = scores.view(x.size(0), self.n_expert_groups, -1)
            scores = scores * group_mask.unsqueeze(-1).expand_as(scores)
            scores = scores.view(x.size(0), -1)

        # Step 3: Top-K 选择
        indices = torch.topk(scores, self.topk, dim=-1)[1]
        # Step 4: 提取并归一化权重
        weights = torch.gather(scores, 1, indices)
        if self.score_func == "sigmoid":
            weights /= weights.sum(dim=-1, keepdim=True)  # 归一化
        weights *= self.route_scale    # x2.5
        return weights, indices

Expert — 单个专家网络

class Expert(nn.Module):
    # 与 MLP 结构相同, 但使用非并行 Linear (专家已通过 EP 分布)
    def __init__(self, dim, inter_dim):
        self.w1 = Linear(dim, inter_dim)       # 7168 -> 1408
        self.w2 = Linear(inter_dim, dim)      # 1408 -> 7168
        self.w3 = Linear(dim, inter_dim)       # 7168 -> 1408

    def forward(self, x):

MoE — 完整混合专家层

class MoE(nn.Module):
    def __init__(self, args):
        self.gate = Gate(args)
        self.n_shared_experts = args.n_shared_experts  # 2
        # 共享专家: 始终激活, 使用 MLP
        self.shared_experts = MLP(args.dim, args.moe_inter_dim * self.n_shared_experts)

        # 专家分片: 每个 GPU 只创建自己负责的专家
        self.n_local_experts = args.n_routed_experts // world_size  # 256/8=32
        self.experts_start_idx = rank * self.n_local_experts
        self.experts_end_idx = self.experts_start_idx + self.n_local_experts

        self.experts = nn.ModuleList([
            Expert(args.dim, args.moe_inter_dim)
            if self.experts_start_idx <= i < self.experts_end_idx
            else None
            for i in range(args.n_routed_experts)
        ])

    def forward(self, x):
        shape = x.size()
        x = x.view(-1, self.dim)           # (N, 7168)

        # 路由
        weights, indices = self.gate(x)    # (N, 8), (N, 8)

        # 初始化输出
        y = torch.zeros_like(x)

        # 统计每个专家收到的 token 数
        counts = torch.bincount(indices.flatten(), minlength=args.n_routed_experts)

        # 遍历本 GPU 的专家, 处理分配到的 token
        for i in range(self.experts_start_idx, self.experts_end_idx):
            if counts[i] == 0:
                continue
            expert = self.experts[i]
            idx, top = torch.where(indices == i)  # 找到分配给专家 i 的 token
            y[idx] += expert(x[idx]) * weights[idx, top, None]  # 加权累加

        # 共享专家: 对所有 token 始终激活
        z = self.shared_experts(x)

        # 分布式: 跨 GPU 聚合路由专家输出
        if world_size > 1:
            dist.all_reduce(y)

        return (y + z).view(shape)

Block — Transformer 块

class Block(nn.Module):
    def __init__(self, layer_id, args):
        self.n_heads = args.n_heads
        self.dim = args.dim
        self.head_dim = args.qk_nope_head_dim + args.qk_rope_head_dim
        self.attn = MLA(args)

        # 关键: 前 n_dense_layers 层用 MLP, 其余用 MoE
        self.ffn = MLP(args.dim, args.inter_dim) if layer_id < args.n_dense_layers \
              else MoE(args)

        self.attn_norm = RMSNorm(args.dim)
        self.ffn_norm = RMSNorm(args.dim)

    def forward(self, x, start_pos, freqs_cis, mask):
        # Pre-Norm 架构 + 残差连接
        x = x + self.attn(self.attn_norm(x), start_pos, freqs_cis, mask)
        x = x + self.ffn(self.ffn_norm(x))
        return x

Transformer — 完整模型

class Transformer(nn.Module):
    def __init__(self, args):
        super().__init__()
        self.embed = ParallelEmbedding(args.vocab_size, args.dim)

        # 创建 61 个 Block
        self.layers = nn.Module.Dict({
            str(i): Block(i, args) for i in range(args.n_layers)
        })

        self.norm = RMSNorm(args.dim)
        self.head = ColumnParallelLinear(args.dim, args.vocab_size)

        # 预计算 RoPE 频率
        self.register_buffer("freqs_cis", precompute_freqs_cis(args))

    def forward(self, tokens, start_pos):
        bsz, seqlen = tokens.size()
        if seqlen == 1:
            # 解码阶段: 无需 mask
            mask = None
        else:
            # 预填充阶段: 因果 mask
            mask = torch.full((seqlen, seqlen), float("-inf"))
            mask = torch.triu(mask, diagonal=1)
            if start_pos > 0:
                mask = torch.hstack([torch.zeros(seqlen, start_pos), mask])

        # Token 嵌入
        x = self.embed(tokens)
        # 提取当前位置的 RoPE 频率
        freqs_cis = self.freqs_cis[start_pos : start_pos + seqlen]

        # 逐层前向传播
        for layer in self.layers.values():
            x = layer(x, start_pos, freqs_cis, mask)

        # 最终归一化 + 输出投影
        x = self.norm(x)
        logits = self.head(x)

        return logits

def forward(self, tokens, start_pos):
    bsz, seqlen = tokens.size()

    # 1. 构造 mask
    if seqlen == 1:  # Decode (逐 token 生成)
        mask = None      # 无需 mask, KV cache 自动处理
    else:           # Prefill (处理整个 prompt)
        mask = causal_mask(seqlen, start_pos)  # 下三角掩码

    # 2. Token 嵌入
    x = self.embed(tokens)         # (bsz, seqlen, 7168)
    if world_size > 1:
        dist.all_reduce(x)     # 词表并行聚合

    # 3. 提取 RoPE 频率
    freqs_cis = self.freqs_cis[start_pos : start_pos + seqlen]

    # 4. 逐层前向传播 (61 层)
    for i in range(self.n_layers):
        layer = self.layers[str(i)]
        x = layer(x, start_pos, freqs_cis, mask)
        # Block.forward 内部:
        #   x = x + MLA(RMSNorm(x), start_pos, freqs_cis, mask)
        #   x = x + FFN(RMSNorm(x))
        #   FFN = MLP (layer 0-2) 或 MoE (layer 3-60)

    # 5. 最终归一化
    x = self.norm(x)

    # 6. 输出投影 (logits)
    logits = self.head(x)        # (bsz, seqlen, 129280)
    if world_size > 1:
        dist.all_gather(logits)  # 列并行输出聚合

    return logits

步骤 1：数据准备

总 token 数 = 15360 × 4096 = 62,914,560 tokens
这些数据来自 14.8T 预训练语料，经过去重、过滤、混合配比

步骤 2：分布式切分

PP=16：模型 61 层被切成 16 个阶段，每阶段约 3-4 层
EP=64：256 个路由专家分布在 64 张 GPU 上，每张 GPU 承载 4 个专家
DP=ZeRO-1：优化器状态在数据并行副本间分片

步骤 3：前向传播

  1. 嵌入层：每个 token 被映射为 7168 维向量，词表并行后 all_reduce
  2. 61 层 Block：每层先 MLA，再 MLP（0-2 层）或 MoE（3-60 层）
  3. 输出头：投影到 129,280 维词表，得到 logits
  4. MTP 模块：D=1，用主模型隐藏状态预测未来 1 个 token

步骤 4：损失计算

主损失   = CrossEntropy(logits, target_tokens)          # 每个位置都参与
MTP 损失 = CrossEntropy(MTP_logits, target_tokens[1:])  # 预测未来 1 个 token
平衡损失 = α × Σ(load_i / N)                            # α 极小，安全网
总损失   = 主损失 + λ × MTP 损失 + 平衡损失

步骤 5：反向传播

  1. 总损失.backward() 触发梯度计算
  2. Distributed Data Parallel 下 all_reduce 同步梯度
  3. FP8 权重在反向时通过 scale 反量化为 BF16 计算梯度

步骤 6：优化器更新

AdamW（BF16 优化器状态）：
  m_t = β1 × m_{t-1} + (1-β1) × g_t
  v_t = β2 × v_{t-1} + (1-β2) × g_t²
  θ_t = θ_{t-1} - lr_t × m_t / (√v_t + ε) - wd × lr_t × θ_{t-1}

其中 lr_t 按余弦调度从 2.2e-4 衰减到 7.3e-6

步骤 7：无辅助损失负载均衡偏置更新

对每个专家 i：
  若 load_i > average_load：b_i -= γ
  若 load_i < average_load：b_i += γ

偏置 b_i 只参与下一次前向的路由选择，不进入反向梯度图

步骤 8：FP8 重新量化

更新后的 FP32 主权重按 128×128 块重新量化为 FP8 E4M3
scale 同步更新，供下一个训练步使用
稳定性：整个 2.664M GPU 小时的预训练过程零回滚、零不可恢复 loss spike，主要得益于细粒度 FP8 量化、无辅助损失负载均衡、以及 DualPipe 对通信和计算的精细重叠。

Absorb 模式矩阵重排推导

Naive 模式需要先把压缩 KV 通过 wkv_b 上投影成完整 K/V 再缓存。Absorb 模式则把 wkv_b “吸收”进 attention 计算，避免缓存完整 K/V。

Naive 模式

kv = wkv_a(x)                        # (B, S, 576)
kv, k_pe = split(kv, [512, 64])
kv = kv_norm(kv)
k = wkv_b(kv)  -> split -> k_nope, v # (B, S, 128, 128) 每个头
k = cat(k_nope, k_pe_expanded)       # (B, S, 128, 192)

缓存 k 和 v，每 token 40,960 维。

Absorb 模式

将 wkv_b 拆分为 K 部分和 V 部分：

wkv_b.weight 形状 = (128 × 256, 512)
reshape -> (128, 256, 512)
K 部分 = wkv_b[:, :128, :]  # (128, 128, 512)
V 部分 = wkv_b[:, 128:, :]  # (128, 128, 512)

注意力分数原本是 q @ k^T，代入 k = K_part @ kv：

scores = q_nope @ k_nope^T + q_pe @ k_pe^T
       = q_nope @ (K_part @ kv)^T + q_pe @ k_pe^T
       = (q_nope @ K_part) @ kv^T + q_pe @ k_pe^T
       = q_nope_c @ kv^T + q_pe @ k_pe^T

其中 q_nope_c = q_nope @ K_part 把 query 投影到 512 维潜空间。

注意力输出原本是 softmax(scores) @ v，而 v = V_part @ kv：

output = softmax(scores) @ (V_part @ kv)
       = (softmax(scores) @ kv) @ V_part

因此只需缓存 512 维 kv 和 64 维 k_pe，共 576 维。

权衡：Absorb 模式每解码步多了两个小矩阵乘（q_nope @ K_part 和 attn_out @ V_part），但这两个矩阵乘的规模远小于加载 40,960 维 KV 缓存的内存开销，因此整体速度更快、显存占用更低。

8 GPU 分布式推理通信量估算

在单节点 8 GPU 推理中，模型被按词表并行、MLA 头并行、专家并行切分。下面估算 batch=1、序列长度=1 的解码步通信量。

1. 嵌入层 all_reduce

每个 rank 只查自己负责的一部分词表，得到部分嵌入向量
all_reduce 聚合完整嵌入
通信量 = 1 × 7168 × 2 B = 14.3 KB

2. MLA wo 的 all_reduce

wo 是 RowParallelLinear，输入按头维度切分到 8 个 rank
每个 rank 计算部分输出后 all_reduce
通信量 ≈ 1 × 7168 × 2 B = 14.3 KB/层
61 层合计 ≈ 873 KB

3. MoE all_reduce

每个 rank 只计算本地专家，结果需要 all_reduce 聚合
通信量 ≈ 1 × 7168 × 2 B = 14.3 KB/层（MoE 层共 58 层）
58 层合计 ≈ 830 KB

4. 输出头 all_gather

head 是 ColumnParallelLinear，输出按词表切分
需要 all_gather 得到完整 logits
通信量 = 1 × 129280 × 2 B = 258.6 KB

每解码步总通信量

约 14.3 + 873 + 830 + 258.6 ≈ 1.98 MB

通过 NVLink（160 GB/s）传输，耗时约 12 μs，远小于计算时间，因此分布式推理扩展性良好。

MTP 投机解码接受率分析

MTP 投机解码的加速比取决于主模型对 MTP 候选 token 的接受率。下面给出定量分析。

设定

  • 主模型每次前向可验证 D 个候选 token
  • MTP 对每个位置生成 1 个候选
  • 单个候选被接受概率为 p

接受长度期望

若 D=1，每步最多接受 1 个候选：

E[接受长度] = p

若 D=k，连续接受 k 个候选的概率为 p^k，则每步平均接受长度：

E[L] = p + p² + ... + p^k = p(1 - p^k)/(1 - p)

加速比估算

设主模型前向耗时 T_main，MTP 前向耗时 T_mtp（约 T_main/50，因为 14B vs 671B）：

传统解码每 token 成本 = T_main
投机解码每步成本     = T_main + T_mtp
每步平均生成 token 数 = 1 + E[L]

加速比 ≈ (1 + E[L]) × T_main / (T_main + T_mtp)
       ≈ (1 + E[L]) / (1 + T_mtp/T_main)

数值示例

假设 p=0.8，D=1，T_mtp/T_main≈0.02：

E[L] = 0.8
加速比 ≈ 1.8 / 1.02 ≈ 1.76 倍

若 D=2，p=0.8：

E[L] = 0.8 + 0.64 = 1.44
加速比 ≈ 2.44 / 1.02 ≈ 2.39 倍
实际取舍：DeepSeek-V3 训练时使用 D=1，因为 D=1 已显著提升性能；推理投机解码可以根据硬件和接受率灵活选择 D。当 p 较低时，投机解码反而可能因为验证失败而增加开销。
